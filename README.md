# atsudori-tools

アツドリのバンド評価値・イベント周回計画・素材の充足日数・スター予算を計算する、非公式の静的Webアプリです。目的別のメニューから各画面を切り替えられます。スマホはヘッダーの「メニュー」から開きます。画面URLの共有とブラウザの戻る／進むにも対応します（[画面移動の仕様・画面例](docs/navigation.md)）。ゲーム運営・開発元とは関係ありません。総合力の計算や編成最適化は対象外です。

**カード等のマスターデータは同梱していません。** ランク推定用のミッション条件・報酬・累積EXPも同梱しません。 利用する権利のあるマスタJSONをImportしてください。外部サービスからの自動取得、ログイン、サーバー、サーバー側DBはありません。マスタがなくても起動し、表示値で個別計算できます。

公開URL: https://morimori36.github.io/atsudori-tools/ （mainへのマージ後、検証成功時に自動デプロイ）

使い方:
1. 「JSON Import / Export」でcatalog JSONをImportします。ランク定義と総合ランクボーナス表もcatalogに含めます。不足は明示され、計算を保留します。
2. 「スタンプ」で所持スタンプを登録します（初期は全未所持、変更は自動保存）。楽曲数はマスタ、スタンプ数は所持からランクへ自動反映します。「メンバー」「スナップ」で所持を切り替え、育成段階を設定します。編集時のLvは段階ごとの上限に連動します。Importした任意の合法Lvは読込だけでは変えません。
3. 「キャラランク」で進捗・ランク、「バンドアイテム」でアイテムLvを登録し、それぞれの画面で保存します。画面切替では未保存入力を保持し、他画面の下書きは保存しません。ランクはランク定義を含むcatalogのImport後に所持・育成から推定し、任意の手入力で上書きできます。総合ランクボーナスは対応する外部ボーナス表から算出するか、画面の加算値を手入力します。旧定義に表がなければボーナスを設定するまで評価値は保留します。未入力進捗は加算せず、未設定アイテムは未知として扱います。
4. 「評価値」でバンド→色→キャラクター→メンバーの内訳を確認します。「現在／育成後」で切り替え、育成後は共通育成条件と絆最大時の理論キャラランクを反映します。条件の要約と「育成条件を変更」ボタンから共通ダイアログを開けます。計算は仮想状態で、所持を変更しません。
5. 「必要素材」で、共通育成条件に基づくメンバー／スナップ別の素材名・必要・在庫・不足の列と消費先を確認します。共有Snapの費用は一度だけ計上します。「素材在庫」は独立した所持管理画面で、個・枚・EXP単位の現在庫を直接編集・自動保存します（空欄は未登録、0は在庫0）。メンバーEXPとスナップEXPは独立した在庫です。Lv途中のEXP進捗はなく、現在Lvと目標Lvの累積EXP差分が必要数です。在庫未登録の不足は未確認、未計算費用がある区分は計算済み小計として表示します。[素材定義と制約](docs/materials.md)を参照してください。
6. マスタと所持JSONはそれぞれExportしてバックアップできます。保存先はこのブラウザ内です。破損データは明示的な復旧操作まで上書きしません。
7. 「JSON Import / Export」で変換プロファイルを登録すると、その定義に沿ったJSONを生成できます。各画面共通の育成条件を任意で適用できます（初期OFF）。ONでは育成後の通常ランクを出力し、絆理論値を含めません。[変換プロファイルの仕様](docs/profile-export.md)を参照してください。

「キャラランク」の横スクロールカードで現在ランク・育成理論値・回収可能EXP（育成＋絆）・理論値から目標までの不足EXPを確認します。目標ランクは共通の数値入力（初期30）で、マスタの合法値だけを確定します。「進捗・ランク入力」「絆内訳」「カード別EXP」はそれぞれ独立して開けます。育成理論値は所持カードを共通条件まで育て、絆も理論上限まで伸ばした状態です。手入力ランク・絆合計は理論計算に使いません。未入力進捗による不確実性は残ります。カード別EXPは所持／未所持を切り替え、それぞれのメンバー／スナップを読み取り専用カードで確認できます。[計算手順・制約](docs/character-rank.md#絆ランク込み理論値)を参照してください。

「表示値で計算」はP/T/Vと補正値を直接入力する、所持とは独立した経路です。評価値計算機の画面例・テストは完全な架空データです。

「イベント周回プランナー」はマスタ登録なしで利用できます。通常・チャレンジ候補を各5件まで入力し、目標ptまでの最小周回数と上位10ペア、全ペアを比較します。1計画で使う候補は通常・チャレンジ各1種類です。CP内訳・推定時間・探索済み範囲も表示します。条件とランク基準は専用のブラウザ保存とJSON Import / Exportで管理します。[計算・入力と制約](docs/event-planner.md)を参照してください。

「スター予算」はcatalogの定義とcollectionの試算条件を使い、週平均スター供給と毎週の全交換費用をアワーノーツパスなし／Lite／Standard／Premiumで横並び比較します。商品別・SRバンド別の全交換とT.G.Wランクを変更できます。実報酬・価格は同梱せず、定義を含むcatalogをImportします。変更は自動保存し、根拠・仮定・未確認を表示します。[使い方・JSON契約](docs/star-budget.md)を参照してください。

Node.js 24.5以降:

```sh
npm ci
npm run dev
npm run check
npx playwright install --only-shell chromium
npm run test:e2e
npm run audit:public
```

開発URLは http://localhost:5173/atsudori-tools/ 、buildは `npm run build`、静的確認は `npm run preview` です。Windowsでは `start-local.cmd` も使えます。npmキャッシュは `.cache/npm` です。

プロファイル出力のSafariエンジン向け追加検証は、`npx playwright install webkit`後に`npm run test:e2e:webkit`を実行できます。iPhone相当のWebKitエミュレーションで、実機Safariの検証とは区別します。

推定式と暫定の選出方針を含み、ゲーム内結果との一致を保証しません。未観測の育成範囲、同レアリティの内部順位、複数代替Snapの割当手順は未検証です。入力・算出結果の利用は利用者自身で確認してください。

静的なカード・育成・ランク・ボーナス表はcatalog、動的な所持・進捗・手入力上書きはcollectionで管理します。ランク定義を含むマスタJSONを「JSON Import / Export」で取り込み、マスタと所持の2ファイルで移行できます。実際の定義・表は初期状態や配信物に含めません。

初期化は「JSON Import / Export」最下部の「データの初期化」を開いて実行します。所持・育成情報（素材在庫、素材供給・スター予算の試算条件、T.G.Wランクを含む）とマスタ（ランク定義、スター予算定義を含む）は別々に初期化します。確認ダイアログが表示され、所持参照が残るマスタ初期化は拒否されます。必要なJSONをExportし、先に所持・育成データを初期化してください。変換プロファイル・共通育成条件・イベントプランナーの保存内容は初期化対象外です。スター予算の旧専用保存キーは読み取らず、移行・復元・削除もしません。[保存・JSON契約](docs/star-budget.md#保存json契約)を参照してください。
