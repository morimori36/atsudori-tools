# 共通ヘッダーと画面移動

PCでは目的別の左サイドバー、700px以下ではヘッダーの「メニュー」から画面を選びます。「評価・計算」「所持・育成」「データ管理」の3群に13画面をまとめ、メンバー／スナップの所持件数と現在位置を表示します。

ヘッダーはスクロール中も表示し、アプリ名・現在画面・保存状態・テーマ選択にアクセスできます。スマホは112pxの2行構成です。長い状態文はヘッダー内では2行まで表示し、全文はtitle属性と各画面のメッセージで確認できます。タイトルと保存状態を省略せず表示するため、その分本文の表示領域を使います。メニューは縦スクロール可能なネイティブdialogで、背景操作を止め、Tabを循環させます。Escape／「閉じる」で起点へ戻り、画面選択後は新しい見出しへフォーカスを移します。PCへ幅を広げると閉じてサイドバーへ戻ります。

画面URLは `#rating`、`#inventory`、`#star-budget` 等のハッシュです。パスとクエリを保持し、静的ホスティングのサブパスで直接リンクとリロードが使えます。不正な識別子は `#rating` に正規化します。戻る／進むも同じ画面切替処理を通り、遷移時は先頭へスクロールします。ページ内の以前のスクロール位置の復元は行いません。

画面切替では既存の自動保存をフラッシュし、手動保存の下書きは保持します。表示値で計算の入力もセッション内で保持します。下書きのリロード後の復元は追加していません。保存キー・計算式・保存タイミングの契約は変更しません。ヘッダーは各計算機の `saveState()` を参照し、破損保護中は保護状態を優先します。

## 検証と画面例

`tests/e2e/navigation.spec.ts` は独立した架空fixtureで13画面への移動、1280/320/375/390pxのライト／ダーク、stickyヘッダー、直接URL・履歴・リロード、キーボード、下書き・自動保存・保存失敗・破損保護を確認します。既存E2Eは共通ヘルパーでスマホのメニュー開閉を経由します。画面例はマスタ・所持とも未登録の空状態です。

画像をソース／配信物に同梱しない既存の公開監査ルールに従い、PNGはGitへ追加しません。PRの「Verify and Pages」チェックの `navigation-review` artifactに次の空状態スクリーンショットを添付します（保持30日）。

- `before-1280.png` / `after-1280.png`: PCの変更前／変更後
- `before-390.png` / `after-390.png`: スマホの変更前／変更後
- `after-390-menu.png`: スマホメニューを開いた状態

再現はbuild後に `node scripts/navigation-screenshots.ts <変更前の完全なコミットSHA>` を実行します。必要なら `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` を指定できます。出力は `.cache/navigation-review` です。比較元は指定コミットから一時ディレクトリへ展開し、空のブラウザプロファイルで撮影します。

Chromiumのビューポートとタッチエミュレーションによる検証で、実機Safariやスクリーンリーダーの読み上げ検証とは区別します。
