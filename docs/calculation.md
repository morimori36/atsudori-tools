# 計算・選出と検証範囲

これはバンド評価値の推定式を実装した非公式ツールです。総合力やメンバー編成の最適化は行いません。選出済みメンバーへのSnap割り当てだけをSnap実効補正合計で最適化します。総合ランクボーナスを独立した入力として扱います。元の実測値・画像・転記・原本はこのリポジトリに掲載しません。

## 表示値からの評価値

Sをメンバー詳細の表示P/T/V、Aを式の覚醒、L/GをLive/撃奏Lv、rをキャラランク、Tを総合ランクの各パラメータへのボーナス、bをバンドアイテムの小数補正とします。

```text
h = (2A + L + G) / 100
C = 5(r - 1) + T
X_i = floor((S_i * (1+h) + C) * (1+b))
B = X_P + X_T + X_V
K = 1 + s_P + s_T + s_V + 0.02U
E = floor(B * K)
```

Tは総合ランクのボーナス欄の値です。個人ランク分を含む合計ボーナスとは区別します。総合ランクの値自体を直接加算しません。手入力を優先し、なければImportしたcatalog.rankDefinition.totalRankBonusesを全キャラの現在ランク合計で参照します。表・対応行・ランク合計が欠ける場合は評価値を保留し、旧固定値へ戻しません。育成後の表示では絆理論値のfinalRank合計で表を引き直し、手入力ボーナスは優先します。

sは表示Snap％の小数倍率、Uは上限解放段階です。SnapなしはK=1として明示的に扱い、ゲーム内Lv0を定義しません。

内部ではBigIntの整数演算を使います。Snap表示3.21%は321（分母10000）、item1.3%は13（分母1000）。各P/T/Vの切捨てと最終切捨てだけを行い、途中で小数を丸めません。安全な整数を超える結果は拒否します。

採用式は非公開に保持する条件明示の転記観測と、仮定を分けた診断に基づきます。転記元の一次画像は再確認できていません。仮定付きの一致を確定実測として数えず、公開側では架空データで演算を検証します。未観測の組み合わせ・高い撃奏Lvなどをゲーム実測済みとは扱いません。覚醒係数2には連動リーダーの寄与が含まれ、独立な寄与を分離したものではありません。

## 育成から表示値へ

メンバーの各チャンネルは、基準Mと対応する3率を使い、次の整数3項を加算します。

```text
Lv項 = floor(f32(f32(M * rateLv) / 10000))
特訓項 = floor(f32(f32(f32(rateTraining) / 10000) * f32(M)))
覚醒項 = floor(f32(f32(M * rateAwakening) / 10000))
表示値 = Lv項 + 特訓項 + 覚醒項
```

f32はIEEE 754 binary32への丸めです。Snap表示％もLv項と同じ順序で基準BPを変換します。一括floorや単純なdouble演算へ変えません。対応していない数値範囲、Lv上限超過、欠けた行、A/UとスキルLvが連動しない形は拒否します。

この育成変換は整数演算とbinary32の丸め順を保つ自作実装です。item補正は対象となる所持アイテムの率を合算します。元の実測資料には個別アイテムLvがなく、全育成範囲や追加表示補正のゲーム検証を完了したという意味ではありません。

## 機械的な選出

選出単位はバンド→色→キャラクター→個別カードです。同一キャラクター・同色のメンバーは、異なるカードなら同レアリティも含め最大3枚をそれぞれ計上します。3枚以内は全員、4枚以上は高レアリティ順で3枚まで選出し、同順位はカードID昇順です。所持情報は変更しません。

旧仮説 **C：バンド・色単位のメンバー評価値合計最大化** は、各メンバー×Snapの丸め後bandRatingを重みにしていました。

新仮説 **E：Snap実効補正合計最大化** は、選出済みメンバーへ割り当てたSnapの `scoreBp` 合計を最大化します。

```text
scoreBp = displayedPerformanceBp + displayedTechnicBp + displayedVisualBp + 200 * snapLimitBreak
maximize Σ(割り当てたSnapのscoreBp)
```

所持Snapの現在Lv・Uから既存の育成変換で算出し、メンバーのステータス・評価値・Snapレアリティを最適化に使いません。同色・対応キャラクターが一致する辺だけにscoreBpを設定し、不一致はnull（禁止辺）、Snapなしは0のダミー列です。装着人数最大化や専用Snap優先を追加しません。

メンバーそのものの選出は変更しません。各メンバー最大1枚、同一バンド・色で各Snap最大1回、別バンドでは再利用します。同一キャラクター・同色の最大3メンバーも維持します。選出後の表示評価値は従来どおり `calculateRating()` で計算し、SnapなしはK=1です。式・丸めを変更しません。育成後は共通条件によるSnap状態で割り当てを再計算します。

実装は長方形のHungarian法による最大重みマッチングです。nを選出メンバー数、sをそのバンド・色で利用可能な所持Snap数とすると、Snapなし用n列を加えて時間O(n²(s+n))、領域O(n(s+n))です。全組み合わせの指数的列挙はしません。catalogは各表20000行・全体50000行、所持JSONは5MiBの制限があり、nは対応キャラクター数の3倍以下です。実マスタは同梱されず、1バンドのキャラ数・Snap数の固定上限は推測しません。架空の18メンバー×2000候補でも検証します。許容JSON上限すべてを単一バンドへ集中させた極端な入力の応答時間は保証しません。

同点は、選出メンバーをID昇順に並べたときの割当Snap ID列の辞書順最小を採用します。Snapなしは全Snap IDより後です。表示行順やImport・オブジェクト列挙順には依存しません。BigIntでSnapスコア合計を第一優先、ID列を第二優先として厳密に比較し、浮動小数点の微小値は加えません。この同点規則も未検証の暫定仕様です。

仮説Eは複数の実機観測を説明するための **試験仕様** で、ゲーム内部の選出アルゴリズムは未確定です。合成テストでは専用・共有Snapの組み合わせ、Cでは評価値が高くなる別配置があってもEがSnapスコアを優先する例、単一メンバーのLvによる逆転を検証します。公開テストは独立した架空データで目的関数と制約を検証し、実機の全候補・数値の一致を証明するものではありません。実機画像・Private由来の生データ・実マスタは追加しません。

ランク・総合ランクボーナス・アイテム不足や評価値計算エラーでも、Snapスコアが算出できればSnapを選出します。評価値は枠ごとに保留理由を保持し、未計算値を0として表示しません。一部が保留なら色・バンドの確定合計はnull、計算できた小計を区別します。未知レアリティでメンバー選出が未確定なら、そのバンド・色の割り当ては保留します。マスタ参照切れ・不正なSnap育成は従来どおり拒否し、スコア0へ補完しません。

同一キャラクター・同色での複数計上と各最大3枚は、ゲームUIの枠数と実機での一例から立てた仮説の試験実装です。確定した内部仕様としては扱わず、今後の観測に合わせて修正します。この仮説だけを理由に計算を保留しません。暫定点は結果の※から読めます。

- メンバー選出の同順位はカードID昇順、Snap割り当て同点は上記ID列順です。ゲーム内tie-breakは未確認です。
- メンバー選出ではEX=SSR、BD=SRの比較順位を暫定適用します。元のrarityを育成や保存で変えません。その他の未知コードの大小は補完せず、競合は保留します。
- Snap実効補正合計最大化（仮説E）は暫定で、関係する枠へ注記します。Snap受取にレアリティ順位は使いません。
- 未設定アイテムを持つ枠は保留します。キャラクターランクは手入力値があれば使用し、なければ[Importした定義でEXPから推定](character-rank.md)します。対応する定義がない場合は推定せず保留します。色またはバンドの一部が保留なら合計も保留し、計算できた小計を区別します。
- 登録がない枠を推測で補完しません。表示合計は登録分です。

「育成シミュレーション」はMemberの特訓・覚醒・Live・撃奏とSnap上限解放を5項目の共通条件で設定します。各選択肢は変更なし・1〜5で、現在値を下げず合法値を選びます。Member／Snap Lvは、段階変更なしでも育成後段階の上限まで育成します。所持保存は変えません。

評価値画面の「現在」は通常の現在状態を評価し、「育成後」と育成余地・素材画面は同じ`simulateTrainingEvaluation()`を使います。育成後状態から既存の絆理論値を計算し、finalRankで個人ランク・全キャラの総合ランク・ボーナス表参照を揃えます。手入力キャラランク・絆合計は理論計算から除外します。手入力総合ボーナスは優先します。理論値が未算出なら評価値は理由付きで保留し、通常ランクへフォールバックしません。

外部JSONは状態生成を共用し、育成後の通常ランク推定（手入力優先）を使います。絆理論値は含めません。必要素材は現在と指定目標の差分です。詳細は[共通育成シミュレーション](training-simulation.md)、[素材計算](materials.md)を参照してください。
