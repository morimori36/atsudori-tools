# シール予算

ガチャの利用有無、有償単発0/1/2回と月上限まで交換する商品だけを選び、30日換算の収入期待値・支出・差引を表示します。定義v2はRメンバー／Rスナップ全完凸・SR／SSR未完凸の固定方式、定義v3は登録済みの実所持方式です。catalogの定義versionだけで切り替え、両方式を混在させません。共通の購入プランとスター供給・交換条件から、スター収支も同じ30日へ換算して表示します。抽選収入は単月の確定取得数ではありません。

catalog v1の任意項目 `sealBudgetDefinition` にversion:2または3、catalogと同じrevision、gachas、productsを登録します。v3はさらにカード別変換条件cardsと排出プールpoolsを必要とします。実定義は同梱しません。構造はcatalog Schema、意味検証は `src/domain/seal-budget/validate.ts` を参照してください。

両versionのgachasはcm/pass/paid/eventの4系統。以下のレアリティ合計確率による計算はv2のみです。名称・周期日数・周期内抽選回数・Rメンバー／Rスナップ／それ以外の確率（10000分率）・各変換シール・1抽選のPt・1Ptのシール・有償スター費用を定義します。確率の既知合計は10000以下、全て既知なら10000が必要です。R変換とPt変換は独立に計上します。paidはPtを保有する前提で、定義の換算量にかかわらずPt収入を計上しません。eventはおはガチャだけでは期間内に天井に達せず、余剰Ptを期限内に交換する想定です。月回数=draws÷periodDays×30、paid（アワーノーツ）とevent（イベント）はそれぞれ独立した選択回数を掛けます。表示前に端数を切り捨てません。

productsは月次シール交換に限定された外部定義です。id/name/tiersを持ち、各tierのsealCost（1交換のシール費用）×monthlyLimit（交換回数）を合算します。商品受取個数は費用に重ね掛けしません。複数枠は一つの商品にまとめてtiersへ保持できます。週次・期間限定・別通貨は生成側で除外します。

## 未確認の扱い（2026-11-13の所有者方針）

予算・供給系シミュレーションでは、数量・確率・報酬・完凸条件・所持状態・価格・上限などの未確認の寄与だけを計算上0とし、既知分の収入・費用・差引を数値表示します。全寄与が未確認でも結果は0です。未確認だけを理由に計算全体や数値表示を止めません。除外した要因は短い注記へ集約し、同じ警告は重複排除します。確率0・Pt0や既知のシール報酬0では、結果に影響しない未知値の注記は出しません。

0への置換は計算処理内だけです。入力オブジェクト、JSONのnull・省略・未登録状態、所持・catalog・保存値は変更しません。不正な形式・負数・重複・破損・参照切れ・計算範囲超過は未確認と区別し、従来どおりエラーです。この例外を、実測値との厳密な一致を要求する評価値計算・育成変換などへ広げません。

collection v1の任意項目 `sealBudgetScenario` はcm/pass（boolean）、paid（0/1/2）、event（省略可の0/1/2）、selectedProducts（重複のない商品ID配列）です。未登録の初期条件は全OFFで、閲覧だけでは保存しません。変更時は既存collectionへ自動保存し、共通JSON Import/Export・初期化・破損保護を使います。保存失敗は未保存と表示し、結果は保存前の条件です。日常Importで項目が省略された場合は以前の条件を保持します。明示的な条件は置き換えます。商品参照を壊すcatalog更新・定義の削除は拒否し、所持を削除しません。

回数は1日あたりです。両有償ガチャの2回選択は、パスの有効期間中に追加枠を利用する試算で、別ガチャを2系統引く意味ではありません。利用可能な回数は外部定義のプラン別上限へ照合し、超過分は両収支から除外して、利用回数を満たせない旨を表示します。イベントガチャの開催が継続すると仮定した30日換算で、実際の開催日数を予測しません。

旧定義v1は意味が異なるため拒否し、v2を含むマスタの再Importへ案内します。所持JSONのpaidは従来のアワーノーツ選択を保持し、省略されたeventは計算時のみ0とします。読込・Exportだけではeventを補完しません。catalog/collection本体のversionは1を維持します。

回数はラジオボタンで選択します。交換費用は「毎月の全交換」の商品一覧に集約し、結果で同じ一覧を繰り返しません。

## 画面構成

ガチャ選択と月上限交換を左の作業領域にまとめ、右の「30日の収支票」で収入−支出＝差引を表示します。各ガチャの操作の横に30日換算の収入期待値を置きます。PCでは収支票をヘッダー下に固定し、高さが足りない場合は票内をスクロールできます。狭い幅では収支票を入力より先に表示し、スマホでは下端にも差引を表示します。下端の表示が最後の入力やページ末尾を隠さない余白を確保します。

ガチャ別のメンバー・スナップ・Pt交換の内訳と試算の前提は、それぞれ独立して開けます。条件変更で閉じません。未知値の除外注記は収支票に常時表示します。負の差引は色と「不足」の文字で区別します。

保存失敗時は入力を残し、収支票・ガチャ別収入・商品費用は保存済み条件による値を維持します。収支票とスマホ下端に変更前の結果であることを示します。破損保護中は入力を無効化し、復旧案内を表示します。計算・保存・Import/Export契約は変えません。


## 実所持方式（定義v3）

所持の正本は既存のcollection.members／collection.snapsです。所持管理での変更・collectionのImport後にシール予算を開くと、その状態で再計算します。シール画面に所持・完凸の再入力欄やコピーの保存キーを追加しません。閲覧や試算だけではcatalog・collectionを書き換えません。共通育成シミュレーションの仮想状態は使用しません。

v3のgachasはid/name/draws/periodDays/pointsPerDraw/sealsPerPoint/paidStarsPerDrawとpoolIdを持ちます。v2のレアリティ合計確率・変換量は受理しません。poolIdでプールを参照する汎用の契約は維持します。2026-11-13に所有者が決定した試算では、全対象ガチャ（パス付属枠を含む）で共通の仮想プールを使います。登録済み全カードを候補とし、特殊レアリティは確率0で表します。実開催ガチャの排出対象リスト・ピックアップ・開催期間は再現しません。

生成側はレアリティ×種別の枠確率を同一区分のカードへ均等配分し、pools[].cards[].probabilityとして用意します。整数化にはprobabilityScaleを使い、枠合計と全体合計を保存します。Publicは生成済みのカード別確率を受け取って計算し、レアリティからの再配分や実開催分布の推測を行いません。Schemaへレアリティ枠や共通poolの制約は追加せず、既存の合計・参照検証を維持します。

| 定義 | フィールドと意味 |
| --- | --- |
| cards[] | kind（member/snap）、cardId（同じcatalogのカードID）、completedAt、beforeCompletion、afterCompletion |
| completedAt | 試算開始時に完凸済みかを判定する覚醒段階／上限解放段階。正整数またはnull。catalog内の該当育成groupの合法段階を参照する |
| beforeCompletion / afterCompletion | 未完凸／完凸の重複獲得報酬を保持する汎用フィールド。今回の試算ではbeforeCompletionは収入に含めず、完凸済みカードのafterCompletionのみ使用する。`{kind: "pieces"}`、`{kind: "none"}`、`{kind: "seals", amount: 非負整数またはnull}`、または条件未確認のnull |
| pools[] | id、probabilityScale（1〜10億の整数）、cards、otherProbability |
| pools[].cards[] | kind、cardId、probability（probabilityScale分率の非負整数またはnull）。同一プールで同一kind＋cardIdは重複不可 |
| otherProbability | カード以外の排出確率。非負整数またはnull。未列挙カードの確率を「その他」へ隠さない |

既知確率の合計はprobabilityScale以下、全確率が既知なら一致を必要とします。端数のあるカード別確率は10000分率へ丸めず、適切な整数分母を選びます。cardsは20000行、poolsは200件、各プールのカードは20000行、全プールのカード行は50000行以内です。全4ガチャのpoolId、プールのカード→変換条件→catalogのカード、completedAt→合法育成段階の参照を検証します。未知version・混在フィールド・参照切れは拒否します。

各カードについて、未所持はシール0。所持は開始時の現在段階がcompletedAt以上の完凸済みカードだけafterCompletionを使います。未完凸の重複（beforeCompletion）はsealsの宣言があっても寄与0です。completedAtがnullなら完凸を推測せず、完凸後も既知のシール0である場合を除いて寄与を未確認とします。piecesとnoneは直接のシール収入0で、後日の任意交換を自動計上しません。sealsのみamountを加算します。「所持している」だけではシール化せず、完凸後でも定義がpiecesならシール0です。Lv・特訓段階・レアリティ・育成表の最大値から完凸を推測しません。

```text
カード寄与/抽選 = probability / probabilityScale × 開始時に完凸済みの場合のシール報酬（それ以外は0）
ガチャのメンバー／スナップ収入 = 対象kindのカード寄与の合計 × 30日換算抽選回数
```

Pt収入、paidでのPt保有、eventの余剰Pt交換、独立した0/1/2回、交換所支出、30日換算はv2と同じ計算を共用します。試算中の所持は開始時の登録状態で固定し、月内の新規排出・ピース蓄積・育成・交換を時系列で再帰反映しません。未確認の扱いは上記専用方針に従い、既知の他カードとPt収入を残します。保存破損は従来どおり復旧まで保護し、画面で空の所持として計算しません。

## 所持モデルとの対応・確認範囲

| 必要情報 | 公開モデルの対応と不足 |
| --- | --- |
| 所持有無 | members[].cardId / snaps[].supportCardId。検証済みcollectionに行がないカードは、既存所持管理と同じ未所持。collectionそのものを取得できない場合とは区別する |
| メンバーの現在段階 | members[].awakeningStage。trainingStage・Lv・キャラランクとは別。試算の完凸境界completedAtと比較する |
| スナップの現在段階 | snaps[].rank（上限解放U）。スキルやLvとは別。試算の完凸境界completedAtと比較する |
| 排出対象・提供割合・重複報酬 | 既存catalog／所持だけでは不足。v3のpoolsとcardsへサービス非依存の宣言として追加する |
| ピース残数・累計獲得数等に依存する変換条件 | 現在の所持段階だけでは判定できない。段階と同一視せずcompletedAt:null等で未知を維持する。未確認の個人状態の追加保存は行わない |

2026-11-13に所有者が、共通仮想プール・枠確率の均等配分・開始時所持固定・完凸済み重複のみのシール寄与を試算仕様として決定しました。completedAtは定義とcatalogの育成グループの合法段階で検証し、Lv・特訓・レアリティから補完しません。これは実開催や実測値との一致を証明するものではありません。架空テストの完凸段階・報酬・排出率はゲーム仕様の根拠ではありません。取得元固有の形式・対応表・原マスタ・実定義・実所持・実測値をPublicへ追加しません。

定義v2は固定方式としてそのまま利用・往復できます。v3への自動変換や部分的な固定前提へのフォールバックはありません。実所持方式にはv3を含むcatalogの明示的な再Importを使います。catalog/collection本体・保存キー・sealBudgetScenarioはv1の既存契約を維持し、所持の移行・再入力は不要です。v3を知らない旧アプリへの逆方向の読込は非対応です。


## 共通ガチャ計画とスター収支

パス4択はcollection.starBudgetScenarioの任意`passPlan`（none/lite/standard/premium）だけへ保存し、両画面から変更できます。省略は計算時のみnone。ガチャの選択は既存のsealBudgetScenarioだけを使います。所持・ランク・イベント／シーズンPremium・交換商品の専用コピーや保存キーは作りません。シールのパス利用チェックは、選択パスに付属する無料特典をまとめて利用する条件です。未購入時はチェックが残っていても無料特典0で、購入を推測しません。

外部catalogのsealBudgetDefinition v2/v3へ任意の`planBenefits`を追加します。指定時はnone/lite/standard/premium全4キーが必要で、各行は次の構造です。

| 項目 | 契約 |
| --- | --- |
| passGachas | 無料特典の配列（0〜20件）またはnull。空配列は特典なし、nullは未確認。noneは空配列必須 |
| passGachas[].gachaId | pass/paid/event。既存ガチャの変換・Pt方針を再利用する参照 |
| passGachas[].draws / periodDays | 周期内の正整数回数と正の日数（各null可）。未知の枠だけを除外し、他の既知枠を残す。数値は既存gachasと同じ範囲。1件の30日回数はdraws×30/periodDays |
| passGachas[].poolId | v3のみ任意。汎用契約として任意の既存pool参照。今回の試算では共通仮想poolを参照する。省略時はそのガチャのpool。v2では不可 |
| paidDailyLimit / eventDailyLimit | 各有償単発の利用上限0/1/2またはnull。無料特典回数を含めない |
| basis | 適用条件・確認範囲を記した空白以外の文字列（300文字以内） |

生成側はプランごとの実際の無料枠・有償枠の条件を確認し、重複しない特典だけを出力します。無料枠は参照ガチャで区別でき、今回の試算では共通仮想poolを使います。付属特典はスター消費0で、既存パスの購入時／毎日スターへ重ねて収入を加えません。無料枠のPt処理も参照ガチャの方針（paidは保有、eventは期限内交換）を用いるため、その方針が成立する特典だけを登録します。

旧catalogも読み込めますが、統合画面でplanBenefitsが欠ける有償枠・購入パスの無料枠は未確認として寄与0と注記します。従来のgachas.passの周期を全プランへ転用しません。未知上限は利用可と推測せず、既知上限を超える選択は選択値を保持したまま超過分だけ計算から除外し、継続可能とは判定しません。未購入に付属特典がないことは既知です。

スターは既存の算術・通貨内訳を共用し、元の周期データから30日供給、週交換費用×30/7、有償ガチャの周期費用を有理数で集計します。総収支は「収入−既存交換−追加ガチャ」。無償供給F、有償供給P、交換E、追加有償ガチャGなら、無償差引=max(0,F−E)、有償の交換充当=max(0,E−F)、有償差引=P−max(0,E−F)−Gです。無料特典の抽選はGへ含めません。二つの通貨・シールの値を合算しません。

総スター赤字、有償不足、シール交換不足、利用回数不一致を区別します。既知分の収入・費用・差引は未確認があっても数値表示し、未知の寄与だけ計算上0にします。欠けた費用があるため黒字になった場合も、未確認ありの試算と表示して継続可能とは断定しません。スター利用制約も判定に残します。未確認とエラーの区別・元データ不変は上記専用方針に従います。

catalog/collection本体・seal定義のversionと保存キーは維持する任意追加です。読込・閲覧・ExportでpassPlanやplanBenefitsを補完せず、自動移行もしません。新項目を知らない旧アプリへの逆Importは非対応です。条件の保存はパス選択とガチャ選択を同じcollectionへ一括で行い、失敗時は両方の旧結果・元保存を保護します。

パス特典・有償単発の上限も権利を持つ外部catalogから受け取り、実定義を同梱せず架空データで検証します。30日平均は継続的な目安で、現在残高、月中の回収・購入・支払い、当日の実行可能性は保証しません。
