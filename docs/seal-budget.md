# シール予算

ガチャの利用有無、有償単発0/1/2回と月上限まで交換する商品だけを選び、30日換算の収入期待値・支出・差引を表示します。定義v2はRメンバー／Rスナップ全完凸・SR／SSR未完凸の固定方式、定義v3は登録済みの実所持方式です。catalogの定義versionだけで切り替え、両方式を混在させません。スター予算には連動しません。抽選収入は単月の確定取得数ではありません。

catalog v1の任意項目 `sealBudgetDefinition` にversion:2または3、catalogと同じrevision、gachas、productsを登録します。v3はさらにカード別変換条件cardsと排出プールpoolsを必要とします。実定義は同梱しません。構造はcatalog Schema、意味検証は `src/domain/seal-budget/validate.ts` を参照してください。

両versionのgachasはcm/pass/paid/eventの4系統。以下のレアリティ合計確率による計算はv2のみです。名称・周期日数・周期内抽選回数・Rメンバー／Rスナップ／それ以外の確率（10000分率）・各変換シール・1抽選のPt・1Ptのシール・参考有償スター費用を定義します。確率の既知合計は10000以下、全て既知なら10000が必要です。R変換とPt変換は独立に計上します。paidはPtを保有する前提で、定義の換算量にかかわらずPt収入を計上しません。eventはおはガチャだけでは期間内に天井に達せず、余剰Ptを期限内に交換する想定です。月回数=draws÷periodDays×30、paid（アワーノーツ）とevent（イベント）はそれぞれ独立した選択回数を掛けます。表示前に端数を切り捨てません。

productsは月次シール交換に限定された外部定義です。id/name/tiersを持ち、各tierのsealCost（1交換のシール費用）×monthlyLimit（交換回数）を合算します。商品受取個数は費用に重ね掛けしません。複数枠は一つの商品にまとめてtiersへ保持できます。週次・期間限定・別通貨は生成側で除外します。

数量・確率・価格・上限のnullは未知のまま保持し、該当する寄与だけ計算上0として短く注記します。既知の他の内訳は表示します。確率0・Pt0なら対応する変換量が未知でも寄与0です。不正な形式・負数・重複・参照切れ・計算範囲超過はエラーです。

collection v1の任意項目 `sealBudgetScenario` はcm/pass（boolean）、paid（0/1/2）、event（省略可の0/1/2）、selectedProducts（重複のない商品ID配列）です。未登録の初期条件は全OFFで、閲覧だけでは保存しません。変更時は既存collectionへ自動保存し、共通JSON Import/Export・初期化・破損保護を使います。保存失敗は未保存と表示し、結果は保存前の条件です。日常Importで項目が省略された場合は以前の条件を保持します。明示的な条件は置き換えます。商品参照を壊すcatalog更新・定義の削除は拒否し、所持を削除しません。

回数は1日あたりです。両有償ガチャの2回選択は、パスの有効期間中に追加枠を利用する試算で、別ガチャを2系統引く意味ではありません。パスの購入状態と自動連動させず、利用可能な条件を選びます。イベントガチャの開催が継続すると仮定した30日換算で、実際の開催日数を予測しません。

旧定義v1は意味が異なるため拒否し、v2を含むマスタの再Importへ案内します。所持JSONのpaidは従来のアワーノーツ選択を保持し、省略されたeventは計算時のみ0とします。読込・Exportだけではeventを補完しません。catalog/collection本体のversionは1を維持します。

回数はラジオボタンで選択します。交換費用は「毎月の全交換」の商品一覧に集約し、結果で同じ一覧を繰り返しません。

## 画面構成

ガチャ選択と月上限交換を左の作業領域にまとめ、右の「30日の収支票」で収入−支出＝差引を表示します。各ガチャの操作の横に30日換算の収入期待値を置きます。PCでは収支票をヘッダー下に固定し、高さが足りない場合は票内をスクロールできます。狭い幅では収支票を入力より先に表示し、スマホでは下端にも差引を表示します。下端の表示が最後の入力やページ末尾を隠さない余白を確保します。

ガチャ別のメンバー・スナップ・Pt交換の内訳と試算の前提は、それぞれ独立して開けます。条件変更で閉じません。未知値の除外注記は収支票に常時表示します。負の差引は色と「不足」の文字で区別します。

保存失敗時は入力を残し、収支票・ガチャ別収入・商品費用は保存済み条件による値を維持します。収支票とスマホ下端に変更前の結果であることを示します。破損保護中は入力を無効化し、復旧案内を表示します。計算・保存・Import/Export契約は変えません。


## 実所持方式（定義v3）

所持の正本は既存のcollection.members／collection.snapsです。所持管理での変更・collectionのImport後にシール予算を開くと、その状態で再計算します。シール画面に所持・完凸の再入力欄やコピーの保存キーを追加しません。閲覧や試算だけではcatalog・collectionを書き換えません。共通育成シミュレーションの仮想状態は使用しません。

v3のgachasはid/name/draws/periodDays/pointsPerDraw/sealsPerPoint/paidStarsPerDrawとpoolIdを持ちます。v2のレアリティ合計確率・変換量は受理しません。poolIdで参照する対象カード集合・提供割合をガチャごとに分け、ピックアップ等の違いも外部定義で表します。同じプールは共有できます。1ガチャのdrawsはすべて同じプールを使います。確定枠等で抽選ごとに分布が異なる場合、生成側で1抽選あたりの正確な混合分布を用意し、レアリティ合計で代用しないでください。

| 定義 | フィールドと意味 |
| --- | --- |
| cards[] | kind（member/snap）、cardId（同じcatalogのカードID）、completedAt、beforeCompletion、afterCompletion |
| completedAt | 所持カードが完凸後の変換へ移る、確認済みの覚醒段階／上限解放段階。正整数またはnull。catalog内の該当育成groupの合法段階を参照する |
| beforeCompletion / afterCompletion | 未完凸／完凸の重複獲得報酬。`{kind: "pieces"}`、`{kind: "none"}`、`{kind: "seals", amount: 非負整数またはnull}`、または条件未確認のnull |
| pools[] | id、probabilityScale（1〜10億の整数）、cards、otherProbability |
| pools[].cards[] | kind、cardId、probability（probabilityScale分率の非負整数またはnull）。同一プールで同一kind＋cardIdは重複不可 |
| otherProbability | カード以外の排出確率。非負整数またはnull。未列挙カードの確率を「その他」へ隠さない |

既知確率の合計はprobabilityScale以下、全確率が既知なら一致を必要とします。端数のあるカード別確率は10000分率へ丸めず、適切な整数分母を選びます。cardsは20000行、poolsは200件、各プールのカードは20000行、全プールのカード行は50000行以内です。全4ガチャのpoolId、プールのカード→変換条件→catalogのカード、completedAt→合法育成段階の参照を検証します。未知version・混在フィールド・参照切れは拒否します。

各カードについて、未所持なら初回カードとして保持しシール0。所持ならcompletedAtと現在段階を比較し、その側の重複報酬を使用します。piecesとnoneは直接のシール収入0で、後日の任意交換を自動計上しません。sealsのみamountを加算します。「所持している」だけではシール化せず、完凸後でも定義がpiecesならシール0です。Lv・特訓段階・レアリティ・育成表の最大値から完凸を推測しません。

```text
カード寄与/抽選 = probability / probabilityScale × 現在の所持状態に対応するシール報酬
ガチャのメンバー／スナップ収入 = 対象kindのカード寄与の合計 × 30日換算抽選回数
```

Pt収入、paidでのPt保有、eventの余剰Pt交換、独立した0/1/2回、交換所支出、30日換算はv2と同じ計算を共用します。試算中の所持は開始時の登録状態で固定し、月内の新規排出・ピース蓄積・育成・交換を時系列で再帰反映しません。カード別条件・確率・シール量・所持スナップショットが未知なら、その寄与だけ計算上0にしてガチャ単位の短い注記へ集約します。既知の他カードとPt収入は残します。元のnullや保存値は変更しません。保存破損は従来どおり復旧まで保護し、画面で空の所持として計算しません。

## 所持モデルとの対応・確認範囲

| 必要情報 | 公開モデルの対応と不足 |
| --- | --- |
| 所持有無 | members[].cardId / snaps[].supportCardId。検証済みcollectionに行がないカードは、既存所持管理と同じ未所持。collectionそのものを取得できない場合とは区別する |
| メンバーの現在段階 | members[].awakeningStage。trainingStage・Lv・キャラランクとは別。これを重複変換の境界に使えることが確認されたカードにのみcompletedAtを登録する |
| スナップの現在段階 | snaps[].rank（上限解放U）。スキルやLvとは別。これを境界に使えることが確認されたカードにのみcompletedAtを登録する |
| 排出対象・提供割合・重複報酬 | 既存catalog／所持だけでは不足。v3のpoolsとcardsへサービス非依存の宣言として追加する |
| ピース残数・累計獲得数等に依存する変換条件 | 現在の所持段階だけでは判定できない。段階と同一視せずcompletedAt:null等で未知を維持する。未確認の個人状態の追加保存は行わない |

この調査で確認したのは、このリポジトリの公開所持・育成モデルと既存の固定方式です。現行JP原マスタ・一次の重複変換仕様は本作業環境に提供されておらず、対応・報酬の実データ検証は未実施です。実ルールを推測で埋めず、確認済み条件だけを外部catalogとして受け取る契約に限定しました。架空テストの完凸段階・報酬・排出率はゲーム仕様の根拠ではありません。取得元固有の形式・対応表・原マスタ・実定義・実所持をPublicへ追加していません。

定義v2は固定方式としてそのまま利用・往復できます。v3への自動変換や部分的な固定前提へのフォールバックはありません。実所持方式にはv3を含むcatalogの明示的な再Importを使います。catalog/collection本体・保存キー・sealBudgetScenarioはv1の既存契約を維持し、所持の移行・再入力は不要です。v3を知らない旧アプリへの逆方向の読込は非対応です。
