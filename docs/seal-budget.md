# シール予算

ガチャの利用有無、有償単発0/1/2回と月上限まで交換する商品だけを選び、30日換算の収入期待値・支出・差引を表示します。Rメンバー／Rスナップは全完凸、SR／SSRは未完凸という試算仮定です。実所持・スター予算には連動しません。抽選収入は単月の確定取得数ではありません。

catalog v1の任意項目 `sealBudgetDefinition` に version:1、catalogと同じrevision、gachas、productsを登録します。実定義は同梱しません。構造はcatalog Schema、意味検証は `src/domain/seal-budget/validate.ts` を参照してください。

gachasはcm/pass/paidの3系統。名称・周期日数・周期内抽選回数・Rメンバー／Rスナップ／それ以外の確率（10000分率）・各変換シール・1抽選のPt・1Ptのシール・参考有償スター費用を定義します。確率の既知合計は10000以下、全て既知なら10000が必要です。1抽選につきR変換とPt変換をそれぞれ一度だけ足します。月回数=draws÷periodDays×30、有償のみ選択回数を掛けます。表示前に端数を切り捨てません。

productsは月次シール交換に限定された外部定義です。id/name/tiersを持ち、各tierのsealCost（1交換のシール費用）×monthlyLimit（交換回数）を合算します。商品受取個数は費用に重ね掛けしません。複数枠は一つの商品にまとめてtiersへ保持できます。週次・期間限定・別通貨は生成側で除外します。

数量・確率・価格・上限のnullは未知のまま保持し、該当する寄与だけ計算上0として短く注記します。既知の他の内訳は表示します。確率0・Pt0なら対応する変換量が未知でも寄与0です。不正な形式・負数・重複・参照切れ・計算範囲超過はエラーです。

collection v1の任意項目 `sealBudgetScenario` はcm/pass（boolean）、paid（0/1/2）、selectedProducts（重複のない商品ID配列）です。未登録の初期条件は全OFFで、閲覧だけでは保存しません。変更時は既存collectionへ自動保存し、共通JSON Import/Export・初期化・破損保護を使います。保存失敗は未保存と表示し、結果は保存前の条件です。日常Importで項目が省略された場合は以前の条件を保持します。明示的な条件は置き換えます。商品参照を壊すcatalog更新・定義の削除は拒否し、所持を削除しません。
