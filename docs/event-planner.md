# イベント周回プランナー

メニューの「イベント周回プランナー」から使います。マスタ・所持情報を登録せずに利用できます。通常候補とチャレンジ候補を各5件まで登録し、「使用する」の候補同士を比較します。名前が空なら登録位置に応じた候補名を表示します。メモ欄はありません。

1計画は通常1候補とチャレンジ1候補を使い続けます。同種候補の混在、カード編成・評価値・外部マスタとの連携は行いません。実行順は通常ライブで必要なCPを確保してからチャレンジライブです。

## 入力と計算

共通条件の初期値は目標525,000pt、現在0pt、現在400CP、通常倍率15、1周2分、探索上限200単位です。CP単位200、チャレンジ1回の最大消費1,600CP（8単位）は固定です。

通常のランク基準（基本pt / 基本CP）はS=75/8、A=50/6、B=35/5、C=25/4。チャレンジの200CP基準ptはSS=5,500、S=4,500、A=3,500、B=2,750です。「ランク基準・探索上限を設定」から編集し、基準だけを初期値に戻せます。

ボーナスは+12%なら12を入力します。ボーナスと分数は小数2桁まで、分数は0より大きい値です。pt・CP・基準値は0以上の安全な整数、通常倍率は1以上の安全な整数です。0の基準値も保持し、達成不能な組み合わせは明示します。空欄や不正値では再計算を保留し、前回の有効な保存内容を上書きしません。

```text
normalPt = floor(基本pt × 通常倍率 × (100 + bonus) / 100)
normalCP = 基本CP × 通常倍率
challengePt = floor(200CP基本pt × (100 + bonus) / 100)
1,600CP獲得pt = challengePt × 8
```

入力された通常倍率が計算の正本です。説明文から倍率を推測しません。200CPあたりの獲得ptを先に切り捨て、消費単位数を掛けます。小数ボーナスは100分の1%の整数に変換し、BigIntで切り捨てを計算します。安全な整数を超える表示結果は拒否します。

各ペアでk=0〜設定上限を両端含めて探索します。

```text
normalForCP = max(0, ceil((k × 200 - currentCP) / normalCP))
normalForPt = max(0, ceil((targetPt - currentPt - k × challengePt) / normalPt))
normalRuns = max(normalForCP, normalForPt)
challengeRuns = ceil(k / 8)
totalRuns = normalRuns + challengeRuns
reachedPt = currentPt + normalRuns × normalPt + k × challengePt
remainingCP = currentCP + normalRuns × normalCP - k × 200
minutes = totalRuns × minutesPerRun
```

除数が0なら、必要量が0以下のとき必要通常回数0、正の必要量があるときそのkは達成不能です。通常・チャレンジとも有効な候補が必要です。k=0の通常ライブだけの計画、目標達成済みの0回も同じ探索で扱います。

ペア内で同じ総周回数ならkが小さい解を採用します。ペア間は総周回数、通常候補の登録順、チャレンジ候補の登録順で比較します。ペア間の同順位をCP消費量で並び替えません。

最短結果と上位10ペア、全有効ペアの結果を確認できます。到達ptが目標以上、残CPが0以上であることを検査します。消費CP内訳は1,600CPの繰り返しと、必要なら200CP刻みの残り1回です。

探索上限は0〜10,000単位、初期値200単位です。設定上限までの全kを探索し、実際の範囲・ペア数・探索数を表示します。**上限を超える解について最短であることは保証しません。** 所要時間は通常とチャレンジが同じ1周時間という仮定です。ゲーム内の全仕様への一致、実機Safariでの操作は別途確認が必要です。

## 保存・JSON

専用キー`atsudori-tools.event-planner.v1`へ有効な編集を自動保存します。表示しただけでは初期値を保存しません。catalogとcollectionの形式・キー・保存内容は変更しません。ネットワーク送信・認証・サーバーは使いません。

JSONは`format: "atsudori-tools/event-planner"`、`schemaVersion: 1`です。全共通条件、候補（name/enabled/rank/bonus）、ランク基準を保持します。CP単位と1回の最大消費CPは固定ルールなのでJSONへ保存しません。構造は[専用Schema](../public/schemas/event-planner-v1.schema.json)を参照してください。

64KiBまでのUTF-8 JSONを読み込みます。必須項目・型・範囲・version・未知のキーを検査し、検証後に「この入力に置き換える」を押して反映します。不正ファイルは現在の入力と保存内容を変更しません。

破損・未対応versionの保存JSONは、元文字列をExportできます。検証済みImportへの明示的な置き換え、または確認付きの「初期値で復旧」まで上書きしません。ブラウザ保存が失敗した場合は未保存と表示し、現在の有効な入力をExportできます。無効な編集中の入力は同じページ内でツールを切り替えても保持しますが、再読み込みでは前回の有効な保存内容へ戻ります。

## 移植時の照合

参照ブックの5シート「ダッシュボード」「入力」「組み合わせ比較」「計算詳細」「ランク基準」の数式・入力・保存済み結果を読み取り専用で確認しました。マクロは実行・移植していません。原本、実際の候補名、メモはリポジトリに含めません。

- 入力：共通条件、各候補の有効設定とランク・ボーナス、通常pt/CP・200CP獲得ptの式。
- ランク基準：通常4ランクの基本pt/CP、チャレンジ4ランクの200CP基本pt。
- 計算詳細：25ペア×201単位=5,025通り。CPとptの必要通常回数の大きい方を採り、チャレンジ回数を加算。
- 組み合わせ比較：ペア内の最小回数と最初に一致するk、ペア間は登録順。
- ダッシュボード：全体最短・内訳・上位10ペア。

依頼に明記された数値ケースで、通常S/+12%とチャレンジA/+146%が87回（80+7）、k=50、使用10,000CP、到達531,300pt、残0CP、174分となり、保存済み結果と一致しました。不一致はありませんでした。公開テストの候補名は完全に架空です。[独立検算](testing.md)に期待値の根拠を記載しています。
