# キャラクターランク定義と推定

推定には利用者がImportしたキャラクターランク定義JSONを使います。ミッション行・閾値・EXP報酬・累積ランクEXP・表示ラベルを同梱しません。アプリやbuildが定義を取得する通信機能もありません。

## 登録とバックアップ

「ランク定義」でJSONを選択し、形式・版・マスタとの内容一致を確認して更新します。現在の定義ID・版、対応マスタ、判定件数・ランク範囲を表示します。所持・マスタと独立した保存キー `atsudori-tools.character-rank-rules.v1` を使い、保存内容を送信しません。更新時のエラーでは以前の保存内容を保ち、破損時は元JSONをExportできます。保存失敗は画面に表示し、メモリ上の定義をExportできます。

端末やサイトを移る前に、マスタ・所持・周回プラン・変換プロファイルに加え、定義JSONもExportしてください。新環境ではマスタ、所持、定義JSONを順にImportします。マスタの版や内容が変わると古い定義では推定せず、対応する定義のImportを案内します。

## 形式と意味検証

[Schema](../public/schemas/character-rank-rules-v1.schema.json)は構造、アプリは意味と互換性を検証します。形式は `atsudori-tools/character-rank-rules`、schemaVersionは1、engineは `achievement-thresholds/1` です。ID・版、対応catalogのID・revision・SHA-256、出典識別子・revision・SHA-256、手入力ラベル、達成条件行、累積ランクEXP行を含みます。対応catalogは正規化した内容全体のハッシュで照合します。

各達成条件行はID、kind、label、stage（対象外ならnull）、thresholds、expを持ちます。対応操作は所持数、育成段階以上の枚数、スキル段階以上の個数、保存済みの手入力進捗です。kind識別子は `members / snaps / training / awakening / snapRank / skills / stamps / songClears / bondRankTotal / liveClears` です。スキル判定は既存の育成対応に従う各スキル値を個別に数えます。任意コードや式、外部URLからの実行には対応しません。

閾値は正整数の厳密な昇順、報酬は正整数です。同一ID、同一kindとstage、手入力キー、出典IDの重複を拒否します。累積EXPは最初の行がEXP0、以後ランクとEXPとも厳密な昇順とし、対応マスタのランク行が必要です。段階指定はマスタの合法行を確認します。件数・深さ・容量・整数演算の上限を検証し、未知項目・形式・版、不一致を推測で補いません。

## 推定と未算出

達成した各閾値の報酬を一度ずつ合計し、累積EXPが条件以上となる最大のランクを選びます。未入力の進捗は不明として保持し、その条件のEXPを加算しません。推定は入力済みの所持・育成・進捗に依存し、達成履歴や報酬の受取状態を再現しません。

定義未登録・不一致では推定EXPも推定ランクも未算出です。EXP0や初期ランクに置き換えません。手入力ランクがあれば優先し、なければ互換性を確認した定義で推定します。使用ランクが未算出の評価値枠と総合ランクは保留し、プロファイル出力にも不足を表示します。全員の手入力ランクがマスタに対応すれば定義なしでもプロファイル出力できます。評価値計算には総合ランクボーナスの手入力または対応するボーナス表も必要です。

所持JSON v1と既存localStorageキーは変えません。`characterRanks`は手入力値のみ、`characterProgress`は既存キーの進捗のみを保存します。定義や推定結果を所持へ混ぜません。旧スキル進捗は互換用に保持し、自動集計へ重複加算しません。現在のマスタにランク行がない手入力値もImport・保存・Exportで保持し、計算・出力時に使用不可を示します。

「育成最大」表示とプロファイルの仮育成は表示・出力用コピーにだけ適用し、ランクは補正前の実所持で算出します。イベント周回プランナーは独立した入力を使います。

## 総合ランクボーナス

定義v1の任意項目`totalRankBonuses`に`{rank, bonus}`の配列を追加できます。rankは総合ランクの閾値（0以上の安全な整数、厳密な昇順）、bonusは各P/T/Vへの加算値（0以上の安全な整数、非減少）です。空配列・重複・降順・未知キーは拒否します。現在の全キャラクターの使用ランク合計以下の最大閾値を使います。実テーブルは同梱しません。

旧定義もImport・EXP推定・Exportに使えます。表のない定義ではボーナスを推測しません。「ランク・アイテム」でゲーム画面の総合ランク分を直接入力すると、所持v1の任意項目`totalRankBonus`に保存し、自動算出より優先します。明示0も有効です。空欄で保存すると上書きを削除します。個人ランク分を含む合計ボーナスを入力しないでください。

定義があってもランク合計が未算出、または該当する閾値がなければ評価値は保留します。手入力ボーナスはランク定義なしでも利用できますが、各評価対象キャラのランクは引き続き必要です。新しい任意項目を含むJSONは旧アプリへ逆方向に読み込めません。
