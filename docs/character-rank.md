# catalog内のランク定義と推定

カード・育成・ランク推定・総合ランクボーナス表は静的なcatalogにまとめます。所持・育成状態・手入力進捗・ランク上書き・ボーナス上書きは動的なcollectionです。通常の移行・バックアップはこの2ファイルで行います。実際のミッション・閾値・EXP・ラベル・ボーナス表は同梱せず、利用者がImportしたcatalogからのみ読みます。

## catalog.rankDefinition

catalog v1への任意項目の追加です。旧catalogも読み込めます。未登録のときはプロパティを省略し、未知の定義を補完しません。新しい任意項目を含むcatalogは旧アプリでは読み込めません。必須項目の削除や意味の置換はありません。

| 項目 | 内容 |
| --- | --- |
| engine | achievement-thresholds/1 |
| id / version | 定義の識別子と版（1〜200文字） |
| provenance.sources | 出典のid・revision・sha256。空でない配列、重複不可、最大100件 |
| manualProgress | 進捗条件のkeyとlabel。旧stamps/songClearsもラベル契約として保持し、実際の手入力はbondRankTotal/liveClearsのみ。重複不可 |
| achievements | 達成条件のid・kind・label・stage・thresholds・exp |
| rankThresholds | 累積EXPとランクの対応。rank・expの配列 |
| totalRankBonuses（任意） | 総合ランクの閾値rankと各パラメータへのbonusの配列 |

旧ファイルのformat・schemaVersion・catalog参照は内包しません。対応するカード・育成表と同じcatalogで検証するため、内部にcatalogのハッシュを重複保存しません。[catalog Schema](../public/schemas/catalog-v1.schema.json)は構造、アプリは参照と演算上限も検証します。定義は新しい独立ファイルや保存キーに分けず、catalogと一緒にImport・Export・保存します。

## 達成条件と未算出

kindはmembers / snaps / training / awakening / snapRank / skills / stamps / songClears / bondRankTotal / liveClearsです。stageは段階条件だけに指定し、対象外はnullです。thresholdsは正整数の厳密な昇順、expは正整数。同一id、同じkindとstage、手入力キー、出典idの重複を拒否します。手入力ラベルと達成条件の対応も必要です。

累積EXPは先頭のexpが0、以後rankとexpとも厳密な昇順です。catalogの合法ランク・育成・スキル段階に対応することを確認します。達成した閾値の報酬を一度ずつ合計し、到達した最大のランクを使います。未入力進捗は加算せず不明として保持します。推定は現在の所持・進捗から行い、受取履歴を推測しません。

手入力ランクがあれば優先します。定義未登録なら推定を行わず、EXP0や初期ランクで埋めません。旧スキル進捗は互換用に保持し、自動集計へ重複加算しません。現在のcatalogに対応行がない手入力も保存・Exportでは保持し、計算時に不足を示します。育成後の評価値には絆理論値を使い、外部JSONの育成条件ONでは育成後の通常ランク推定を使います。

## 絆ランク込み理論値

「キャラランク」の選択中バンドの各キャラカードに、使用ランク・通常推定と区別して「絆最大時」の最終理論ランクを小さく表示します。途中値や絆合計の一覧表は表示しません。説明は「絆最大時とは」をタップ・クリック・キーボードで開いて確認できます。5人の横並びとcatalog由来の表示順を維持し、表示順未指定の旧catalogでは従来の2,4,1,5,3順を使います。登録済みの所持・育成・進捗を使い、編集中の進捗は保存操作後に反映します。

絆ランクは、次の5項目を確定仕様として扱います。

- 同一バンド内のキャラクター2人の組み合わせごとに絆ランクが存在する。
- 5人バンドでは10ペア。
- 各ペアの絆ランク上限は`min(キャラAのランク, キャラBのランク)`。
- 各ペアの絆ランク初期値は1。
- 各キャラの絆ランク合計は、そのキャラを含む全ペアの絆ランクの合計。

バンド間の絆は扱いません。

計算用コピーで`characterRanks`の上書きと`characterProgress.bondRankTotal`だけを除外し、既存エンジンで絆なしの自動推定を行います。他の所持・育成・進捗と旧互換項目は保持します。各ペアを1に初期化し、現在ランクからペア上限へ更新、絆合計をコピーへ設定、既存エンジンで再推定する手順を、キャラランクとペアランクの両方が変わらなくなるまで繰り返します。ミッションEXP・達成閾値・累積ランクEXPは、通常推定と同じcatalog.rankDefinitionを参照します。

報酬・閾値が正かつ昇順の検証済み定義では、更新は単調非減少です。絆なし推定から開始することで、初期状態から到達可能な最小不動点を求めます。高いランクを先に仮定して、自己整合するだけの到達不能な値を採用しません。バンド人数をn、ランク閾値行数をLとすると、ランクが増加する反復は最大n×(L−1)回です。最後のペアのみの更新と安定確認を含め、n×(L−1)+2回を安全な停止上限とします。行間のランク番号が連続することは仮定しません。単調性違反、安全整数を超える絆合計、上限内での未収束は数値を返しません。

ランク定義や絆合計の達成条件がない場合、ランク行が不一致の場合、不正なマスタ・所持・進捗、空の対象バンドは未算出です。定義や不明値を推測で補いません。絆以外の未入力進捗は通常推定と同様に加算せず、不確実性を表示します。同じバンドの他キャラの未入力もペア上限に影響するため、表示値は実機で確定した到達値ではありません。

この結果は育成後の評価値へ反映します。現在の評価値・通常の推定・保存されたランク上書き・絆合計の手入力は変更せず、保存・Import/Exportの形式も変更しません。現在のペアランクの入力、必要な絆EXP・ライブ回数・ブースト消費量、保存値への自動反映は対象外です。この実装作業での計算結果の実データ照合や実機検証は行っていません。

## 総合ランクボーナス

表はcatalog.rankDefinition.totalRankBonusesに置きます。総合ランクの閾値rankは0以上の安全な整数、厳密な昇順。bonusは各P/T/Vへの加算値で、0以上の安全な整数、非減少です。空配列・重複・降順を拒否します。各計算状態で使う全キャラのランク合計以下の最大閾値を参照します。表をコード内の式へ置換しません。

collection.totalRankBonusの明示的な手入力があれば優先し、0も有効です。空欄で保存すると上書きを削除します。表・対応閾値・ランク合計が欠ける場合は評価値を保留します。個人ランク分を含む合計ボーナスと区別してください。

## 定義の管理

「JSON Import / Export」でrankDefinitionを含むマスタJSONをImportしてください。旧独立JSONの移行UI・旧保存キーからの読み込みは廃止しました。旧保存キーの内容は変更・削除しません。

マスタはrankDefinitionも含む全置換です。定義なしのマスタも検証後に反映し、定義未登録・不一致では推定を停止します。「キャラランク」から適切なマスタJSONのImportを案内します。既存の所持・進捗・ランク上書きは保持します。

「JSON Import / Export」最下部の「データの初期化」でマスタを初期化すると、内包するランク定義も削除します。所持・育成データが参照している場合は拒否し、先に必要な操作を表示します。

## 生成器が出力する形式

既存catalogのルートに、上表のrankDefinitionオブジェクトを追加してください。総合ランク表はそのtotalRankBonusesです。旧ファイルをそのままネストせず、format・schemaVersion・catalogを除いた静的な定義本体を内包します。動的なcharacterProgressやcharacterRanksをここへ入れないでください。

## 育成シミュレーションでの比較

評価値の育成後と育成余地・素材は同じ共通条件・計算処理を使います。育成後状態から既存の絆反復計算を実行し、全キャラのfinalRankを個人ランクと総合ランク・ボーナス表参照へ適用します。総合ボーナスの明示的手入力は優先します。現在の手入力ランクや絆進捗は保存されたままで、理論計算では除外します。理論ランクと参考の通常推定は区別します。

絆定義欠落や不一致時は理由付きで保留します。通常ランク・手入力への代替は行いません。外部JSONは育成後状態から通常ランクを推定し、手入力を優先しますが、絆理論値は使いません。[全条件と保存移行](training-simulation.md)を参照してください。

## 楽曲・スタンプの自動算出

楽曲クリア種類数はcatalog.songClearCounts、スタンプ所持種類数はcatalog.stampsとcollection.ownedStampIdsから算出します。楽曲ごとの所持やクリア履歴は登録しません。スタンプ管理で所持・未所持を切り替え、名称・対象キャラ・所持状態で絞り込めます。変更は自動保存し、保存できなければ直前の所持状態を保持します。

キャラランク画面ではこの2項目を閲覧専用で表示し、達成条件内訳にも同じ値を使用します。手入力は絆ランク合計・ライブクリア数、ランク上書きは従来どおりです。旧スタンプ数・楽曲数の保存値を計算や不足判定へ使用しません。定義がない旧catalogでは両方0、ランク定義なしなら推定不能です。全計算経路で同じ推定関数を使い、絆・育成後・素材画面・外部JSON出力へも適用します。閾値・EXP・式は変更していません。
