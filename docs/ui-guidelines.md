# 画面共通のUI設計ルール

目的は、操作方法をラベル・配置・状態から予測できることです。操作説明の重複を減らしても、計算の前提、未確認、データ保護の理由は残します。全画面を同じレイアウトや保存方式にする規則ではありません。

## 現行13画面の棚卸し

調査対象は `src/ui/app.ts` と各画面のTS/CSS、既存E2Eです。素材別充足日数の #54/#55 による44px入力、意味ごとのfieldset、短い近接補足、前提のdetailsを基準に参照します。本PRで他画面を改修しません。

| --- | --- | --- | --- |
| 評価値（app.ts、training-settings） | 現在／育成後のradio、育成条件dialog | 結果先行、内訳details、暫定方針の注記 | 所持を変更しない試算は維持。選択中・単位・詳細への導線を明確にする |

同じ意味の「含める／除外する」checkbox、単位付き数値、短い補足、折りたたみ詳細、結果表の数値組版は統一候補です。排他選択radio、所持状態button、合法Lvの±、ファイルImportは意味が違うため一律置換しません。

## 情報の階層と順序

1. 画面タイトルは共通シェルのh1を1つ。目的は短い概要で示す。
2. 主要操作／主要結果にはh2。関連入力にはfieldset・legendを使う。
3. 詳細設定・内訳はdetails。重要な注意をdetailsだけに閉じ込めない。
4. 計算の根拠・例外・未確認理由は、対応する結果や条件から到達させる。

入力しないと意味のある結果が出ない画面は入力先行（素材充足・表示値計算）。保存条件を繰り返し比較する画面は結果先行（イベント周回・今回のスター予算）。順序は画面の目的と実データ量で決め、CSSのorderで読み上げ順だけを変えない。

スター予算は11商品の全交換条件より先に、同条件の「週平均総供給／週費用／差引／判定」を4パスで示します。「試算条件へ」のリンクで入力へ移動でき、条件の直後にも比較へ戻る導線を置きます。結果先行では保存失敗時に古い結果を最新と誤認しないよう、結果付近に「変更前の条件による結果」と明示します。

## 操作部品

Vanilla HTMLの意味を保ち、色やスイッチ形状で意味を作りません。今回導入する `src/ui/form-patterns.ts` と `form-patterns.css` はopt-inです。他画面の `.field`、`.check`、保存処理を書き換えません。

| 役割 | ルール・例 |
| --- | --- |
| 数値入力 | `uiNumberField`。明示label、単位、合法なmin/max/step、空欄の意味。16px・44px以上、右揃え・tabular-nums。例「ストーリー付きイベント割合（%）」＋「0%=なし / 100%=毎回あり（全話回収）」 |
| 複数の独立ON/OFF | `uiCheckbox`。native checkbox＋全ラベルを44px以上の操作領域にする。補足はaria-describedbyで結ぶ。例「シーズンミッションPremiumを購入」 |
| 排他選択 | radio＋fieldset/legend。少数の段階なら現在の段階ボタンを使い、複数ON可能なcheckboxにしない |
| 選択肢が多い入力 | native select＋label。未設定は具体的な値と区別。数値入力と同じ高さを使う |
| ステッパー | ±buttonは操作名を持ち、合法値で止める。未知・未解放を勝手に最小Lvにしない |
| 一次操作 | 既存 `.primary`。例「試算して条件を保存」。自動保存画面に形だけの保存ボタンを追加しない |
| 二次／危険操作 | `.secondary`、破壊的なら `.danger` と削除対象・必要な確認。色だけで危険を伝えない |
| 詳細 | native details/summary、summaryも44px以上。展開状態は再計算で保持する |

使用例（値と文言はhelper内でエスケープ。raw HTMLを引数へ渡さない）:

```ts
uiNumberField({id:'budget-rank', name:'scenario.rank', label:'T.G.Wランク', value:rank, min:1,
  help:'キャラランクと共有。空欄は未確認。'});
uiCheckbox({id:'budget-season', name:'scenario.seasonPremium', label:'シーズンミッションPremiumを購入', checked:true});
```

共通CSSの `.ui-fields`、`.ui-group`、`.ui-help`、`.ui-feedback`、`.ui-details` は配置と表現だけを扱います。型・計算・保存・入力の採否は各画面が担当します。既存のテーマ変数、一次／二次button、panelを再利用します。

## 説明文とフィードバック

説明は次の3種類に分類します。

| 分類 | 表示場所・残す内容 | スター予算での扱い |
| --- | --- | --- |
| 操作に必要な短い補足 | 入力の直下。aria-describedbyで対応付け | ランク共有・空欄の意味、ストーリー割合の両端、アリーナ反復報酬の存在確認 |
| 結果の解釈・仮定・根拠 | 結果付近の短い前提＋詳細 | 週平均の概算は常時表示。全回収・周期・価格段階・根拠は既存の内訳detailsへ。円/30日は円と明示しスターに混ぜない |
| 保護・未確認など重要な注意 | 影響する操作／結果のそばに常時表示 | 保護中は操作を無効化。未知の差引は算出不可、理由を既定展開。保存失敗時は変更前の条件による結果であることを表示 |

ラベルで伝わる操作を長文でも繰り返さない一方、仮定を「確認済み」に言い換えたり、未確認を0で補完しません。計算可否は元のドメイン結果に従います。

| 状態 | 表示・挙動の原則 |
| --- | --- |
| 自動保存 | 共通ヘッダーは実際のsaveStateを参照。条件付近で保存先と方式を短く示す。保存ボタンを追加しない |
| 明示保存／未反映 | 保存・反映buttonと近接状態を残す。別画面の下書きを勝手に保存しない |
| 未保存／入力不正 | 入力を保持し、問題の入力にaria-invalid、近接メッセージを関連付ける。計算結果の条件が古いことを示す |
| 保存失敗 | 失敗を成功にしない。確定データ・結果を維持する既存契約に従い、再試行可能な入力を残す |
| 破損保護 | 元JSONを上書きせず、復旧先を示す。disabledだけで理由を省略しない |
| 計算保留 | 保存失敗と区別し、「算出不可／未確認」と具体的な理由、既知小計を示す。色だけに依存しない |

スター予算の保存方式・画面再訪時の未確定入力の扱いは [既存契約](star-budget.md#保存json契約) のままです。設計ガイドのために保存タイミングや破損保護を変更しません。statusは短い更新に使い、比較表全体を毎キー入力で読み上げさせません。

## レスポンシブとアクセシビリティ

- 320/375/390/1280pxとライト／ダークで、入力とラベルの対応、44px以上のタップ領域、キーボード・フォーカス・文字コントラストを確認する。
- 入力列は内容に応じて折り返す。長い商品名・根拠は折り返し、ページ全体を横にはみ出させない。
- 比較表は一つのスクロール領域に保つ。caption・列／行見出しのscope・領域名・キーボードフォーカス・スクロールの短い案内を付ける。4種類を別の画面に分けない。
- スター予算では行ラベルを左固定、列見出しを表の縦スクロール中も上固定とする。固定セルは不透明背景にし、数値を透かさない。スマホでは全列の同時表示より読みやすい列幅を優先する。
- 長い根拠はdetailsへ置くが、保留・古い結果・破損保護の表示は常時到達可能にする。外部データは必ずテキストとしてエスケープする。

## 新規画面・変更時のチェックリスト

- [ ] 画面の目的と主要操作／結果が、長文説明の前に見つかるか。入力先行／結果先行の理由はあるか。
- [ ] 同じ意味の部品・単位・余白・タップ領域を再利用し、仕様上違う操作まで統一していないか。
- [ ] label、fieldset/legend、scope、aria-describedby、フォーカス、エラーの読み上げが対応しているか。
- [ ] 操作補足／計算の仮定／重要な警告を区別し、必要な根拠を残しているか。
- [ ] 自動保存・明示保存・未保存・保護・計算保留を正確に表示しているか。
- [ ] 4幅・2テーマで、入力／結果がある完全な架空データを使って検証したか。
- [ ] 入力→再計算→保存→再読込、未知、失敗、保護、他画面への影響を検証したか。
