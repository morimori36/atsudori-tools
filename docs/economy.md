# 基本素材需給シミュレーター

追加交換・課金なしの通常プレイによる素材供給と、目標育成に対する不足を試算します。必要素材は現在の所持・共通育成条件から `calculateMaterialRequirementsToTarget()` で算出し、`materialInventoryBalances()` で登録在庫と比較します。所持状態・在庫は変更しません。

対象は通常ライブ・スキップ、スタジオ練習、ランク報酬、通常プレイの継続的な固定報酬、標準イベントです。通常プレイによるスターも資源ID別に集計できます。購入・費用・用途配分は扱いません。

## 標準イベント

供給定義は supplyDefinition.schemaVersion=3。standardEvent は intervalDays（正整数の開催間隔）、basis（仮定の根拠）、cumulative（累計全回収分）、limited（個数制限商品全回収分）を持ちます。未登録はnull。各報酬は fixed・lotteries・unavailable の配列です。

生成側で累計全回収分と個数制限商品だけの素材を集約し、バッジ自体・余剰分・無制限商品を除外します。アプリには個別イベントID・期間・到達pt・商品情報を取り込みません。

想定開催回数＝期間日数÷開催間隔。小数回を切り捨てずに標準報酬へ乗じ、確定供給・抽選期待値と別の「推計」として記録します。10日間隔なら30日で3回、365日で36.5回相当。開始日によって開催回数は変わりません。10日は暫定仮定であり、外部定義の値・根拠を画面と結果Exportへ表示します。イベント全回収は常に達成する前提です。

## 表示と前提

資源別に必要・現在庫・基本供給・イベント推計・総供給・推定不足・充足期間を表示します。抽選期待値は明細で確定供給と区別します。必要数未計算・在庫未登録・供給定義不足では全体の不足と充足期間は未確認です。既知の小計と未知の理由を残し、未知を在庫0・報酬0とは扱いません。

充足期間は今回の平均日次供給が継続する場合の日数（切上げ）です。正確な達成日を保証しません。供給0では到達を推定しません。

ライブは期間LBを通常・スキップへ配分し、スキップ分を切り捨てます。直接EXPは在庫と分離します。練習は蓄積単位・受取間隔・上限・効率・ランク倍率・端数処理を使い、不明な規則は保留します。

その他の継続報酬は fixedSources に id/name/basis、reset、window、rewards を登録します。resetはdaily/weekly/monthlyと時点を明示し、受取回数を試算条件へ指定します。window=nullは期間制限なしです。費用・有料区分・一度きりの商品は定義しません。

## 保存と互換性

供給はcatalog内、実在庫はcollection内、試算条件はschemaVersion=4の独立JSONです。保存キーは atsudori-tools.economy-scenario.v4。旧v1〜v3は非対応。旧保存は自動変換・上書きせず、元JSONをExportしてからv4をImportするか、確認付きで試算条件を初期化できます。catalog・collection本体の既存形式は維持します。

供給定義の旧v2も非対応です。生成側ではv3に更新し、passes・standardEvent.activeDays、固定報酬のcategory/priceYenを除去し、通常プレイの継続報酬だけを出力する必要があります。現行Private側の旧出力はそのままImportできません。今回Privateの実装・元データは変更していません。

試算条件のImport/Export、結果・育成条件・使用版・根拠・全明細のExportを利用できます。破損保存を保護し、Import失敗は既存条件を維持します。実マスタ・個人情報は同梱せず、公開検証は独立した架空データです。
