# 素材別充足日数シミュレーター

共通育成条件による必要量、collectionの素材在庫、継続的な日平均供給から、素材ごとの充足日数を概算します。素材の相互変換や編成最適化は行いません。必要量は `calculateMaterialRequirementsToTarget()`、不足は `materialInventoryBalances()` を共用します。

## 入力と保存

T.G.Wランクは `collection.tgwRank`、Premium購入状態は `collection.starBudgetScenario.eventPremium / seasonPremium` をスター予算と共用します。独立したランクや購入状態は保持しません。

素材供給だけの条件はcollection v1の任意 `supplyConditions` に保存します。

| 項目 | 内容 |
| --- | --- |
| lbPerDay | 非負の安全な整数。1日に消費するLB |
| scoreRank | 通常ライブのスコアランク。未設定はnull |
| studioLevels | bandId・levelの組。空配列は練習なし |

未指定時の画面上の条件はLB 0・スコア未設定・練習なしです。読込やExportだけで既存collectionに条件を書き足しません。入力の変更時に自動保存し、同じ入力DOMを保持するのでフォーカスは移動しません。不正な途中入力と保存に失敗した入力は、実際に編集した項目だけを画面移動後も下書きとして保持します。未編集のランク・Premium状態などは最新collectionから表示し直すため、他画面での変更を古い下書きで巻き戻しません。結果は直前の保存済み条件のままにします。再読込で復元するのは保存成功した条件です。

共通collectionのImport/Export・復旧・初期化を使います。通常ImportでsupplyConditionsを省略すると既存条件を保持し、明示すると空配列・0・nullも含め全体を置換します。完全復元での省略は保持しません。旧専用条件JSONとv1〜v5の保存キーは読み取り・移行・復旧・Export・書込みを行いません。

## 日平均供給

- ライブは指定スコアランクの固定報酬と抽選期待値を `lbMultiplier × lbPerDay` 倍します。抽選は基本数量×当選重み÷総重みで合算します。未設定・欠落の寄与だけを計算上0とし、既知報酬を残します。重複定義や参照不整合はエラーです。
- スタジオはLv入力済みバンドが24時間通常効率で稼働し、効率低下前に回収する前提です。内部回収周期を `normalMinutes` とし、周期内のtick数×ランク倍率×rewardScaleを固定数量・抽選回数へ掛け、受取ごとに切捨てて `1440/normalMinutes` 回／日で平均化します。日末受取・効率低下・上限は計算せず、ユーザーの受取設定は増やしません。在庫EXPに練習自体のEXP補正は適用しません。
- ランクのデイリー報酬は毎日全回収。標準イベントも全回収を継続する前提です。
- その他の継続供給は既存の `event-pass-free / event-pass-premium / season-pass-free / season-pass-premium` のIDを使います。無料は常時全回収、Premium追加報酬は対応する共通購入状態がONのとき全回収、OFFなら除外します。任意の受取率はありません。欠落分は計算上0とし注記します。
- イベントは10日ごとに切り替わり、継続開催されるものとして計算します。`EVENT_INTERVAL_DAYS` はスター予算と共通のツールの仮定で、ゲームの確定日程ではありません。標準イベントとイベントミッションの換算に適用します。シーズンの換算日数は供給定義を使い、不明分は計算上0とします。

供給定義は `supplyDefinition.schemaVersion=5` です。スタジオの受取時切捨てを契約として固定し、旧rounding・lotteryRounding・overflowRate・capMinutesは受理しません。旧v4は数値の意味を黙って変えず、再生成・マスタ再Importを案内して拒否します。旧方式への分岐・自動変換はありません。所持・在庫は削除せず、catalog v1とcollection v1自体の版は変更しません。

## 結果と不確実性

6列は素材・必要量・現在庫・不足量・日平均供給・充足日数です。不足量は `max(0,既知必要量−(現在庫??0))`、充足日数は `ceil(不足量÷既知日平均供給)`。分数合算後に切上げます。全量が未確認でも計算上の必要量0・不足量0なら0日です。不足0なら0日、不足あり・供給0なら「現在の条件では充足不可」です。

未確認の需要・供給と未登録在庫は計算上のみ0とし、元データの不明状態や保存値は変更しません。未確認があるときだけ除外内容を注記します。供給の欠落は日数を長く、需要の欠落は短く見積もりえます。未登録在庫の0仮定は不足量を多く見積もりえます。確定した全量や達成日ではありません。不正入力・破損定義・参照不整合・数値範囲超過はエラーとし0へ変換しません。

## 補足UIの棚卸し

| 残す要素 | 操作・判断上の必要性と削除しない理由 |
| --- | --- |
| マスタ・所持の保護通知 | 破損保存のため編集不能である理由と、共通復旧先を知らせる |
| 保存・入力エラー、未反映状態 | 入力値が保存・結果へ反映されたかを区別し、失敗した値を採用済みと誤認させない |
| イベントの短い1文 | 10日間隔の継続開催がツールの仮定であると判断できるようにする |
| 日平均の概算・抽選期待値の1文 | 平均値を確定した実取得数や達成日と誤認させない |
| 現在の条件では充足不可 | 計算上の供給0を恒久的な入手不能と区別する |
| 未確定理由の一覧 | 計算に含まれない入力・定義を特定する。同じ理由は重複表示しない |
| 共通フッターの非公式表示・検証範囲リンク・権利表示 | ゲーム公式機能と誤認させず、未検証範囲と第三者の必須表示を確認できる共通の入口 |
| 画面冒頭の用途説明 | 充足日数が日平均供給による育成素材の概算であることを、結果が出せない状態でも確認できる |
| 共通育成条件の操作 | 必要素材の目標を変更する入口。素材供給専用の説明を追加しない |

イベント抽出経緯・Issue番号・basis表示、ランク説明、受取率説明、各供給の計算前提、内訳・根拠の詳細、結果の読み方の折りたたみ、往復ジャンプボタン、重複する凡例、条件JSONと専用初期化、結果Exportは撤去します。削除した設定を非表示の互換モデルとして残しません。
