# 素材別充足日数シミュレーター

共通育成条件による必要量、collectionの素材在庫、継続的な日平均供給から、素材ごとの充足日数を概算します。素材の相互変換や編成最適化は行いません。必要量は `calculateMaterialRequirementsToTarget()`、不足は `materialInventoryBalances()` を共用します。

## 入力と保存

T.G.Wランクは `collection.tgwRank`、Premium購入状態は `collection.starBudgetScenario.eventPremium / seasonPremium` をスター予算と共用します。独立したランクや購入状態は保持しません。

素材供給だけの条件はcollection v1の任意 `supplyConditions` に保存します。

| 項目 | 内容 |
| --- | --- |
| lbPerDay | 非負の安全な整数。1日に消費するLB |
| scoreRank | 通常ライブのスコアランク。未設定はnull |
| studioLevels | bandId・levelの組。空配列は練習なし |

未指定時の画面上の条件はLB 0・スコア未設定・練習なしです。読込やExportだけで既存collectionに条件を書き足しません。入力の変更時に自動保存し、同じ入力DOMを保持するのでフォーカスは移動しません。不正な途中入力と保存に失敗した入力は画面移動後も下書きとして保持し、結果は直前の保存済み条件のままにします。再読込で復元するのは保存成功した条件です。

共通collectionのImport/Export・復旧・初期化を使います。通常ImportでsupplyConditionsを省略すると既存条件を保持し、明示すると空配列・0・nullも含め全体を置換します。完全復元での省略は保持しません。旧専用条件JSONとv1〜v5の保存キーは読み取り・移行・復旧・Export・書込みを行いません。

## 日平均供給

- ライブは指定スコアランクの通常ライブ1件の `perLb × lbMultiplier × lbPerDay`。LB 0ならライブ報酬を計上しません。スコアランク未設定・定義の欠落や重複は計算保留です。スキップ・実行回数・直接付与EXPは日平均素材供給の条件にしません。外部定義に回数依存の在庫報酬があれば、その影響素材は保留し、0とはみなしません。
- スタジオはLv入力済みのバンドだけを通常効率で24時間／日として計算します。`1440 / tickMinutes` とランク倍率・rewardScaleを使います。受取周期・蓄積待ち・溢れ・受取上限という状態は持ちません。tick丸めは定義どおり各単位で処理します。claim丸めは各単位が整数で受取周期に依存しない場合だけ使い、受取周期によって変わる端数の扱いは推測せず保留します。未設定Lvは除外、不正Lv・未知の倍率や丸めは正常供給として扱いません。
- ランクのデイリー報酬は毎日全回収。標準イベントも全回収を継続する前提です。
- その他の継続供給は既存の `event-pass-free / event-pass-premium / season-pass-free / season-pass-premium` のIDを使います。無料は常時全回収、Premium追加報酬は対応する共通購入状態がONのとき全回収、OFFなら除外します。任意の受取率はありません。必要な定義の欠落は供給0へ補完しません。
- イベントは10日ごとに切り替わり、継続開催されるものとして計算します。`EVENT_INTERVAL_DAYS` はスター予算と共通のツールの仮定で、ゲームの確定日程ではありません。標準イベントとイベントミッションの換算に適用します。シーズンの換算日数は供給定義を使い、不明なら保留します。

供給定義は既存の `supplyDefinition.schemaVersion=4` を維持します。ユーザー条件を減らすために供給定義の形やバージョンを変えません。

## 結果と不確実性

6列は素材・必要量・現在庫・不足量・日平均供給・充足日数です。不足量は `max(0,必要量−現在庫)`、充足日数は `ceil(不足量÷日平均供給)`。分数で合算してから切上げ、表示の丸めを計算へ戻しません。既知の必要量を既存在庫が満たすなら0日、不足があって供給0なら充足不可、入力・需要・必要な供給が不明なら算出不可です。

抽選は期待値です。未登録の在庫を0と扱いません。必要量が未確定なら既知の小計を表示し、充足日数を確定しません。供給の不確実性は対象素材へ適用し、対象が不明なら全素材を保留します。正確な達成日や抽選での到達確率は保証しません。

## 補足UIの棚卸し

| 残す要素 | 操作・判断上の必要性と削除しない理由 |
| --- | --- |
| マスタ・所持の保護通知 | 破損保存のため編集不能である理由と、共通復旧先を知らせる |
| 保存・入力エラー、未反映状態 | 入力値が保存・結果へ反映されたかを区別し、失敗した値を採用済みと誤認させない |
| イベントの短い1文 | 10日間隔の継続開催がツールの仮定であると判断できるようにする |
| 日平均の概算・抽選期待値の1文 | 平均値を確定した実取得数や達成日と誤認させない |
| 未登録・未確認・小計・算出不可・充足不可 | 未知と0、供給不足と条件不足を区別する |
| 未確定理由の一覧 | 算出不可を解消するために必要な入力・定義を特定する。同じ理由は重複表示しない |
| 共通フッターの非公式表示・検証範囲リンク・権利表示 | ゲーム公式機能と誤認させず、未検証範囲と第三者の必須表示を確認できる共通の入口 |
| 画面冒頭の用途説明 | 充足日数が日平均供給による育成素材の概算であることを、結果が出せない状態でも確認できる |
| 共通育成条件の操作 | 必要素材の目標を変更する入口。素材供給専用の説明を追加しない |

イベント抽出経緯・Issue番号・basis表示、ランク説明、受取率説明、各供給の計算前提、内訳・根拠の詳細、結果の読み方の折りたたみ、往復ジャンプボタン、重複する凡例、条件JSONと専用初期化、結果Exportは撤去します。削除した設定を非表示の互換モデルとして残しません。
