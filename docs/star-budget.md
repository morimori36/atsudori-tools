# スター予算

「スター予算」で、カタログ商品を毎週上限まで全交換する費用と、継続的な週平均スター供給を比較します。アワーノーツパスのなし／Lite／Standard／Premiumを同じ条件で横並びにします。正の差引はガチャ・貯蓄へ回せる平均余剰、負なら継続全交換にスターが不足する試算です。

実ゲームの報酬・価格・解放条件・周期は同梱しません。JSON Import / Exportからスター予算定義を含むcatalogを登録してください。定義がなければ計算できない旨を表示します。定義は読み取り専用で、供給の内訳・根拠と前提、価格の根拠から確認できます。

## 画面の構成

最初に4種類の比較表を表示し、週平均総供給・全交換費用・差引・判定をまとめます。「試算条件へ」でランク・イベント、供給に含める報酬、商品別の全交換条件へ移動できます。変更は従来どおり所持データへ自動保存し、失敗時は直前の確定条件による結果であることを表示します。

スマホは比較表を横スクロールして確認できます。行名を左固定し、表内の縦スクロールではパス名を上固定します。短い操作補足は入力のそばへ、計算の前提・価格・報酬の根拠は結果の詳細へ置きます。未確認による保留と保存失敗は別の状態です。[共通UIルール・判断と検証方法](ui-guidelines.md)を参照してください。

## catalog／collection統合

catalog v1の任意項目 `starBudgetDefinition` に静的値・根拠・未確認区分を保持します。構造は従来のdefinitionと同じで、定義のrevisionはcatalogのrevisionと一致必須です。全11商品、価格段階、区分と値・根拠の整合性を検証します。定義なしの旧catalogも有効です。

collection v1の任意項目 `starBudgetScenario` は次の5項目だけを必須にします。ランクは既存の `tgwRank` のみで、scenarioにrankは保存しません。

| 項目 | 型・読み取り時の既定値 |
| --- | --- |
| storyEventPercent | 0〜100の整数またはnull（既定null） |
| eventPremium / seasonPremium | boolean（既定false） |
| includeArena | boolean（既定false） |
| selectedProducts | 重複しない既知商品ID配列（既定は全11種、空配列も有効） |

省略された条件を保存・Export時に補完しません。通常Importで項目がなければ保存中の条件を保持し、明示された条件はfalse・null・空配列を含め丸ごと採用します。完全復元では省略分を保持しません。catalog更新・定義の有無によって既存の条件や所持を削除しません。未確認を0に置き換えません。

画面の条件変更は共通のcollection保存経路を使います。Import/Export・初期化はJSON Import / Export画面から行います。旧独立JSONと専用保存キーは読み取らず、移行・復元・削除もしません。

## 入力・計算

マスタの根拠区分は未確認・仮定・確認済みを区別します。「確認済み」は登録者の申告です。画面ではTGWランク、Premium購入2種、ストーリー割合、アリーナ、交換商品だけを変更できます。TGWランクはキャラランク画面と共通で、空欄は不明です。

| 供給源 | 週平均の計算と条件 |
| --- | --- |
| 通常ログイン／デイリーミッション | 各1日分×7 |
| ライブスタンプ | 1週分をそのまま計上。報酬選択の前提が必要。通常ログインには含めない |
| イベント累計pt／ミッション無料 | 1イベントの全回収スター÷想定間隔（日）×7 |
| イベントミッションPremium | 無料分を除く追加スターだけを同周期で換算、購入ON時のみ |
| ストーリー | 1話スター×全回収話数×ストーリー付き割合/100÷イベント間隔×7。割合0はなし、100は毎回あり |
| シーズン無料／Premium | 各1シーズン分÷換算日数×7。Premiumは無料分を除く追加スター、購入ON時のみ |
| アリーナ・プラチナ1 | 反復スター÷周期×7、含める設定ON時のみ。初回到達報酬・チケットは登録しない |
| アワーノーツパス | 購入時スター÷継続更新日数×7＋毎日スター×7 |

周期は実日程ではなく想定値です。継続購入し、各回の対象報酬と毎日スターを全回収する前提です。Premium追加スター0なら購入切替で収支は変わりません。無料ガチャ・チケット・素材・シールはスターへ換算しません。

有償／無償スター等をカタログ支払で合算できるかを「利用条件」で登録します。合算できると仮定／確認し、根拠を設定した場合に差引を出します。未確認や利用制約ありなら供給・費用を残して差引を保留します。制約別の資金繰りは扱いません。

円価格は別の行です。パスの1契約の円価格÷更新日数×30を参考の30日負担とします。暦月額ではなく、イベント／シーズンPremium料金も含みません。円が未確認でもスター収支は計算できます。

## 全交換

クリスタル2商品・チケット4商品は商品別、SRピースは5バンド枠別にON/OFFします。SR枠は対象バンドを区別できる商品名に変更してください。商品名の重複は拒否します。

各商品に解放T.G.Wランクと1〜20段階の価格・週上限を登録します。「1交換のスター価格×その段階の週交換上限」を全段階・選択商品で足します。上限は交換回数です。複数個セットを1交換とする商品は商品名にセット内容を明記します。任意の購入数量や最適化・推奨はありません。

解放ランク未満の商品は、価格が不明でも費用から除外します。選択は保持し、ランク上昇時に再計上します。交換OFFも0費用。選択商品の解放条件・入力ランクが不明なら解放を推測せず保留します。価格・上限の不明時も既知分の小計と未確認を区別します。

## 保存・JSON契約

静的定義はcatalog v1の `starBudgetDefinition`、個人条件はcollection v1の `starBudgetScenario`、ランクはcollectionの `tgwRank` が正本です。[catalog Schema](../public/schemas/catalog-v1.schema.json)・[collection Schema](../public/schemas/collection-v1.schema.json)と意味検証を併用します。

definitionはrevision、loginDaily、missionDaily、liveStampWeekly、liveStampSelection、event、season、arena、passes、starCompatibility、starCompatibilityBasis、productsを持ちます。productsは全11商品（crystal-luck、crystal-miracle、skill-live、skill-gekisou、skill-basic、skill-sp、sr-1〜sr-5）を各1回持ち、name、unlockRank、1〜20段階のtiers[{starCost, weeklyLimit}]を定義します。数値と根拠は `{value, status, basis}` で、nullはunconfirmed、数値ありはassumedまたはconfirmedと空白以外のbasisが必要です。日数は正の小数2桁以内、数量・価格は非負安全整数、解放ランクは正整数です。

起動・表示では保存しません。有効な条件変更は保存成功後に確定します。保存失敗や不正入力では共通の未保存警告を表示し、確定済みcollectionと計算結果を保持します。画面を切り替えると未確定の条件は破棄し、共通collectionから読み直します。破損した所持・マスタは保護し、スター予算の変更・計算を止めます。復旧は共通のImport／初期化を使います。マスタ更新では所持の条件を上書きしません。

## 外部定義の生成と未確認範囲

この契約に供給・周期・購入時／毎日スター・利用制約・全商品枠と価格段階を出力してください。ログインとスタンプ、無料とPremium追加、初回と反復を生成側でも分離し、各値の出典・適用シーズン・選択条件をbasisへ記録します。実定義は利用者が管理し、公開repo・テスト・初期配信物へ追加しません。

実ゲームの定義確認や外部の実データ変換器の追加・変更は行っていません。実報酬、パスの更新・回収条件、価格段階、週上限、解放ランク、反復アリーナ報酬の有無、スターの合算可否は未確認です。未確認を0にせず、仮定を確認済みと扱わないでください。

内部は有理数で換算・集計し、表示時に小数最大2桁へ丸めます。0でない絶対値0.01未満は指数表記で符号を保ちます。安全な数値範囲を超える計算は拒否します。週平均は獲得時刻・一時不足・実購入可否を保証しません。在庫への交換報酬計上、購入操作、ガチャ期待値、課金推奨、数量最適化、日時別残高、実日程は対象外です。
