# スター予算

「スター予算」で、カタログ商品を毎週上限まで全交換する費用と、継続的な週平均スター供給を比較します。アワーノーツパスのなし／Lite／Standard／Premiumを同じ条件で横並びにします。正の差引はガチャ・貯蓄へ回せる平均余剰、負なら継続全交換にスターが不足する試算です。

実ゲームの報酬・価格・解放条件・周期は同梱せず、すべて未確認から始めます。「定義・根拠」で入力するか、この画面でExportした専用JSONに合わせて外部で作成した定義をImportしてください。catalog・所持・素材別充足日数の定義／条件とは独立し、マスタなしでも利用できます。

## 入力・計算

各数値に値・根拠の区分・適用範囲を登録します。空欄は未確認、0は明示的な0です。数値を変更すると「仮定」へ戻し、根拠が空なら「手入力の仮定」を設定します。「確認済み」は登録者が根拠を確認して切り替える区分で、アプリが実ゲームの値を確認したという意味ではありません。

| 供給源 | 週平均の計算と条件 |
| --- | --- |
| 通常ログイン／デイリーミッション | 各1日分×7 |
| ライブスタンプ | 1週分をそのまま計上。報酬選択の前提が必要。通常ログインには含めない |
| イベント累計pt／ミッション無料 | 1イベントの全回収スター÷想定間隔（日）×7 |
| イベントミッションPremium | 無料分を除く追加スターだけを同周期で換算、購入ON時のみ |
| ストーリー | 1話スター×全回収話数×ストーリー付き割合/100÷イベント間隔×7。割合0はなし、100は毎回あり |
| シーズン無料／Premium | 各1シーズン分÷換算日数×7。Premiumは無料分を除く追加スター、購入ON時のみ |
| アリーナ・プラチナ1 | 反復スター÷周期×7、含める設定ON時のみ。初回到達報酬・チケットは登録しない |
| アワーノーツパス | 購入時スター÷継続更新日数×7＋毎日スター×7 |

周期は実日程ではなく想定値です。継続購入し、各回の対象報酬と毎日スターを全回収する前提です。Premium追加スター0なら購入切替で収支は変わりません。無料ガチャ・チケット・素材・シールはスターへ換算しません。

有償／無償スター等をカタログ支払で合算できるかを「利用条件」で登録します。合算できると仮定／確認し、根拠を設定した場合に差引を出します。未確認や利用制約ありなら供給・費用を残して差引を保留します。制約別の資金繰りは扱いません。

円価格は別の行です。パスの1契約の円価格÷更新日数×30を参考の30日負担とします。暦月額ではなく、イベント／シーズンPremium料金も含みません。円が未確認でもスター収支は計算できます。

## 全交換

クリスタル2商品・チケット4商品は商品別、SRピースは5バンド枠別にON/OFFします。SR枠は対象バンドを区別できる商品名に変更してください。商品名の重複は拒否します。

各商品に解放T.G.Wランクと1〜20段階の価格・週上限を登録します。「1交換のスター価格×その段階の週交換上限」を全段階・選択商品で足します。上限は交換回数です。複数個セットを1交換とする商品は商品名にセット内容を明記します。任意の購入数量や最適化・推奨はありません。

解放ランク未満の商品は、価格が不明でも費用から除外します。選択は保持し、ランク上昇時に再計上します。交換OFFも0費用。選択商品の解放条件・入力ランクが不明なら解放を推測せず保留します。価格・上限の不明時も既知分の小計と未確認を区別します。

## 保存・JSON契約

formatは`atsudori-tools/star-budget`、schemaVersionは`1`、保存キーは`atsudori-tools.star-budget.v1`。条件と定義を1つのJSONで管理します。[構造Schema](../public/schemas/star-budget-v1.schema.json)に加え、`src/domain/star-budget/validate.ts`の意味検証が必要です。

| 項目 | 内容 |
| --- | --- |
| definition.revision | 英数字開始、英数字・ピリオド・下線・ハイフンの1〜80文字の版 |
| definition.loginDaily / missionDaily / liveStampWeekly | 数値と根拠の組 |
| definition.liveStampSelection | スタンプの報酬選択。正のスターを含める場合は必要 |
| definition.event | intervalDays, points, missionFree, missionPremium, storyPerEpisode, storyEpisodes |
| definition.season | intervalDays, free, premium |
| definition.arena | intervalDays, recurringStars（反復分のみ） |
| definition.passes | lite / standard / premiumごとのperiodDays, purchaseStars, dailyStars, priceYen |
| definition.starCompatibility | unconfirmed / assumed-usable / confirmed-usable / restricted |
| definition.starCompatibilityBasis | 合算可否の根拠。未確認以外は必須 |
| definition.products | 全11商品。id, name, unlockRank, tiers[{starCost, weeklyLimit}] |
| scenario | rank, storyEventPercent, eventPremium, seasonPremium, includeArena, selectedProducts |

商品idは`crystal-luck`、`crystal-miracle`、`skill-live`、`skill-gekisou`、`skill-basic`、`skill-sp`、`sr-1`〜`sr-5`。ツール内の固定枠で上流ゲームIDを解釈しません。各枠は必ず1回、選択idは重複なし。配列順はImport/Exportで保持します。

数値と根拠は`{value, status, basis}`。statusは`unconfirmed` / `assumed` / `confirmed`です。valueがnullならunconfirmed、数値があればassumedまたはconfirmedと空白以外のbasisが必要です。数量・円・価格・上限は0以上の安全な整数、ランクは1以上。日数は0より大きい小数2桁以内、最大安全整数/100以下。storyEventPercentはnullまたは0〜100の整数、rankのnullは不明です。根拠は300文字、商品名は200文字まで。未知キー・危険キー・不正型・未対応versionを拒否し補完・型変換しません。UTF-8で256KiBが上限。再Importできない大きさのExportも拒否します。

起動・表示だけでは保存せず、有効な変更ごとに専用キーだけを自動保存します。手動入力の保存失敗ではメモリ内の条件を保持し、未完了を表示してExport・再試行できます。不正入力は未保存の下書きとして画面切替後も保持し、結果を隠します。

Importは検証・計算・保存に成功したときだけ反映します。新しい入力・Import・初期化に追い越された古いImportは無視します。破損・旧形式の保存は元文字列を保持して自動保存を停止し、元JSONをExportできます。確認付きImportか初期化で復旧します。保存に失敗したImport・初期化では現在の条件と保護状態を維持します。保存を読めない場合も未知の既存値を自動で置き換えません。

## 外部定義の生成と未確認範囲

この契約に供給・周期・購入時／毎日スター・利用制約・全商品枠と価格段階を出力してください。ログインとスタンプ、無料とPremium追加、初回と反復を生成側でも分離し、各値の出典・適用シーズン・選択条件をbasisへ記録します。実定義は利用者が管理し、公開repo・テスト・初期配信物へ追加しません。

実ゲームの定義確認や外部の実データ変換器の追加・変更は行っていません。実報酬、パスの更新・回収条件、価格段階、週上限、解放ランク、反復アリーナ報酬の有無、スターの合算可否は未確認です。未確認を0にせず、仮定を確認済みと扱わないでください。

内部は有理数で換算・集計し、表示時に小数最大2桁へ丸めます。0でない絶対値0.01未満は指数表記で符号を保ちます。安全な数値範囲を超える計算は拒否します。週平均は獲得時刻・一時不足・実購入可否を保証しません。在庫への交換報酬計上、購入操作、ガチャ期待値、課金推奨、数量最適化、日時別残高、実日程は対象外です。
