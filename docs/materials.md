# 育成余地・素材

現在のcollectionの全所持Member・Snapを**追加ガチャ・凸なしで最大育成**した場合の成果と費用を比較します。今回の投資判断は既存所持の育成だけが対象です。課金額、ガチャ期待値、素材所持数・不足数、育成効率の最適化、バンドアイテムの素材は扱いません。

## 目標状態と育成成果

`src/app/maximum-training.ts`の`maximumTrainingTarget`は、[共通育成条件API](training-simulation.md)の凸なし最大プリセットを使って検証済みcollectionから独立した計算用コピーを作ります。

- 所持カード・Memberの覚醒段階・Snapの上限解放段階は維持します。
- Memberの特訓・ライブ／撃奏スキルは対応group／スキル配列の合法な最大値、Lvは最大特訓段階のrarity別上限へ設定します。特訓が既に最大でもLvを上限へ設定します。
- Snap Lvは現在のrankの上限へ設定します。rankの最大値のLv上限は使いません。
- 手入力ランク・進捗・総合ランクボーナス上書き・バンドアイテム・その他の所持項目を維持し、既存の検証ロジックで目標を再検証します。未確認の段階依存を追加しません。

素材は`calculateMaterialRequirementsToTarget`で現在→目標の費用を計算します。既存の`calculateMaterialRequirements`（覚醒・Snap rankも最大にする汎用計算）は互換用に維持しますが、この画面の費用合計には使いません。覚醒・Snap上限解放の現物要求は今回の合計へ入りません。catalog／collectionの形式・保存内容は変更しません。

手入力ランクは両側で維持し、キャラ詳細には参考の自動推定の前後も表示します。未入力進捗は通常推定と同様に加算しません。評価値・総合ランクボーナスとその計算説明・暫定選出の注記は、この画面には表示しません。共通シミュレーションの計算、評価値画面、JSON出力の仕様は変更しません。

絆詳細は初めて開いたバンドで、同じ目標モデルから既存の反復計算を実行し、画面内では結果を共有します。表示は**育成後かつ絆EXP獲得後の理論上限**です。ペア別上限、絆最大時の理論キャラランク、実際の獲得済み絆ランクを区別します。実際のペアランクは保存していないため未登録と表示し、絆EXP獲得・ランク上昇を実行しません。理論計算では従来どおり手入力ランク・絆合計を除外します。理論キャラランクを育成後の通常ランク・評価値へ適用しません。

## 表示と集計範囲

表示順は育成条件、必要素材合計、バンド・キャラ別内訳、Snapの必要素材・カード内訳です。現行画面の条件は凸なし最大育成固定で、条件編集ダイアログは未実装です。独立した育成成果の概要は設けず、ランク比較は各キャラの内訳で確認します。

- バンドを展開：Member素材小計、ペア絆上限、各キャラのランク前後。
- キャラを展開：自動推定・手入力の区別、関係するペア絆上限、Member素材小計、所持Member。
- カードを展開：素材小計、未達の育成項目の費用・段階。根拠と維持／達成済み項目はさらに詳細へ。
- Snapは別の折りたたみで小計とカード内訳を確認します。

展開は**全所持カードを最大育成する単一シナリオの内訳**です。「そのバンド／キャラだけ育成する」シナリオ切替ではありません。Member費用は所属キャラ・バンドへ帰属させ、共有Snap費用を対応キャラやバンドへ重複加算しません。全体は各Memberと各Snapを一度ずつ合算します。バンド小計は「Member分」と明記します。

通常素材・ゲーム内通貨はマスタの素材名・単位で表示し、EXP要求量は分けます。汎用素材定義には希少性・通貨専用の分類がないため、名前／IDから優先順位や分類を推測しません。注意は該当箇所に短く表示し、計算条件・根拠・保留理由は詳細から参照できます。

素材定義を含むcatalog JSONを「JSON Import / Export」のマスタからImportしてください。定義を持たない既存catalogも引き続き有効です。

## 定義契約

catalog v1の任意項目`materialDefinition`に以下を内包します。別の保存キーは作らず、collectionの形式・保存バイト列を変更しません。実定義は同梱せず、ブラウザから取得・変換・送信しません。

| 項目 | 内容 |
| --- | --- |
| catalogRevision | 包含するcatalogのrevisionと完全一致する識別子 |
| resources | 素材のid・name・unit（item:個、card:枚、exp:EXP要求量） |
| schedules | id・axis・mode・basis・stages、任意のreason |
| bindings | kind（member/snap）・cardId・axis・scheduleId |

axisはMemberの`trainingStage`・`awakeningStage`・`liveSkillLevel`・`gekisouSkillLevel`・`level`、Snapの`rank`・`level`です。名称と費用の根拠`basis`は提供者が登録し、画面ではテキストとして表示します。

scheduleのmodeは`steps`（到達段階ごとの消費）、`cumulative`（その段階までの累計）、`unsupported`（確認できない費用）です。stagesは`stage`と`amounts: [{resourceId, quantity}]`を持ちます。配列順は意味を持ちません。初期段階のsteps費用は空配列または明示0、以後の消費なしも空配列で明示します。行の欠落を消費0とは解釈しません。unsupportedには空のstagesと必須のreasonを設定します。

計算はstepsなら現在値より大きく目標以下の行を合算し、cumulativeなら目標の累計から現在の累計を引きます。累計から省略した素材は0として扱うため、以前存在した正の数量を省略して減らす定義は拒否します。素材の種類をまたいで数量を足しません。安全な整数の範囲を超える合計はエラーにします。

素材・費用IDの重複、素材やカードの参照切れ、育成軸の不一致、合法段階の欠落・未知の段階、減少する累計、版不一致はImport時に拒否します。費用bindingの省略は許可し、その育成項目を計算不能にします。100素材/段階、1000段階/定義、全体50000段階、素材・定義・binding各20000件、JSON全体10MiBが上限です。識別子・説明・整数はcatalogの一般規則に従います。

汎用の全段階最大計算では、最大段階は対応groupの最大の段階・スキルLv・rank、Lvの目標は最大特訓段階または最大Snap rankのLv上限です。この画面では上記の凸なし目標を明示的に指定します。Lv費用表には対応groupの全Lvを登録しますが、上限より先は計算に含めません。既に最大なら追加費用はなく、費用定義が未登録でも計算上は達成済みとし、画面では維持・達成済みの詳細へまとめます。

## EXPと未計算

EXPはLv軸のcumulativeだけに対応します。計算結果は「目標Lvの累計EXP − 現在Lvの累計EXP」で、現在Lvの開始時点からの要求量です。collectionはLv内の途中EXPを保存していないため、これを実際の残り必要EXPとは断定しません。画面と全体集計に上限である旨を表示し、EXPアイテムの効果や個数へ換算しません。

費用定義の欠落・unsupportedは0とせず、項目ごとに理由を表示します。一部が計算不能なら全体は計算済み分の小計です。EXPの上限と確定した素材個数は区別して表示します。異なる費用ルートや代替素材がある場合は、提供者が選んだルートの根拠をbasisに明記してください。代替の選択・最適化機能はありません。

catalogのImportは従来の参照保護と保存失敗保護を使用します。無効なImportは既存catalog/collectionを変更しません。既存のcatalog/collection Export、ランク、評価値、仮育成、変換プロファイルは維持します。旧catalog本体を対象にする互換用ハッシュは新しい任意定義を除外します。
