# 育成余地・素材

現在のcollectionの全所持Member・Snapを**3画面共通の育成条件まで育てた場合**の成果と費用を比較します。素材在庫を手動登録し、全体必要量との差分も確認できます。課金額、ガチャ期待値、育成効率の最適化、バンドアイテムの素材は扱いません。

## 目標状態と育成成果

評価値画面と同じ`simulateTrainingEvaluation()`で仮想状態を作ります。5項目の目標は「変更しない」または1〜5、現在値を下げず合法な値だけを使います。Member／Snap Lvは段階維持時も育成後の段階に対応する上限へ設定します。共通ダイアログ、旧4項目設定の移行・保存保護は[共通育成シミュレーション](training-simulation.md)を参照してください。

素材は`calculateMaterialRequirementsToTarget()`で現在→目標の差分だけを計算します。覚醒・Snap上限解放を指定して上がる場合、その現物要求も含みます。未知の費用は未計算です。catalog／collectionを変更せず、入力進捗・手入力・アイテム・その他の所持情報を保持します。

絆理論値は`result.bondTheory(bandId)`のready結果をそのまま表示し、手入力キャラランク・絆合計を除外します。pendingでは数値を補完せず理由を表示します。評価値画面・JSON出力・保存形式・計算仕様は変更しません。

## 表示と集計範囲

表示順は共通育成条件、必要素材、絆理論値です。

- 必要素材は既存の`result.materials.totals`と`resources`を使い、素材名と総量を常時表示します。展開すると`cards[].axes[].amounts`を素材IDで逆引きしたカード×育成項目別の消費先を表示します。同一カードの特訓と覚醒も別行です。各消費先の合計は総量と一致し、共有Snapは一度だけ含まれます。
- 費用の根拠・理由・現在→目標は消費先の計算詳細で確認できます。未計算項目は独立した詳細に集め、素材IDが不明な項目を特定素材に関連付けません。一部未計算なら総量は計算済み分の小計です。
- 絆理論値はキャラランク入力画面と同じ表示順で、finalRank（最終キャラランク）とbondRankTotal（最終絆合計）を常時表示します。各キャラを展開すると関係するペアとrankを表示します。ペアは両キャラに表示し、それぞれの合計がbondRankTotalと一致します。未入力進捗の注意を維持します。

条件変更時は両セクションと展開内容を更新します。理論上の到達値であり、獲得済みの絆ランクではありません。バンド・キャラ単位の素材小計、カード階層、独立したSnap内訳は設けません。

通常素材・ゲーム内通貨はマスタの素材名・単位で表示し、EXP要求量は分けます。汎用素材定義には希少性・通貨専用の分類がないため、名前／IDから優先順位や分類を推測しません。注意は該当箇所に短く表示し、計算条件・根拠・保留理由は詳細から参照できます。

素材定義を含むcatalog JSONを「JSON Import / Export」のマスタからImportしてください。定義を持たない既存catalogも引き続き有効です。

## 定義契約

catalog v1の任意項目`materialDefinition`に以下を内包します。別の保存キーは作りません。素材在庫はcollection v1の任意項目で、在庫なしの旧collectionは従来どおり読み込めます。読込だけでは保存バイト列を書き換えません。実定義は同梱せず、ブラウザから取得・変換・送信しません。

| 項目 | 内容 |
| --- | --- |
| catalogRevision | 包含するcatalogのrevisionと完全一致する識別子 |
| resources | 素材のid・name・unit（item:個、card:枚、exp:EXP要求量） |
| schedules | id・axis・mode・basis・stages、任意のreason |
| bindings | kind（member/snap）・cardId・axis・scheduleId |

axisはMemberの`trainingStage`・`awakeningStage`・`liveSkillLevel`・`gekisouSkillLevel`・`level`、Snapの`rank`・`level`です。名称と費用の根拠`basis`は提供者が登録し、画面ではテキストとして表示します。

scheduleのmodeは`steps`（到達段階ごとの消費）、`cumulative`（その段階までの累計）、`unsupported`（確認できない費用）です。stagesは`stage`と`amounts: [{resourceId, quantity}]`を持ちます。配列順は意味を持ちません。初期段階のsteps費用は空配列または明示0、以後の消費なしも空配列で明示します。行の欠落を消費0とは解釈しません。unsupportedには空のstagesと必須のreasonを設定します。

計算はstepsなら現在値より大きく目標以下の行を合算し、cumulativeなら目標の累計から現在の累計を引きます。累計から省略した素材は0として扱うため、以前存在した正の数量を省略して減らす定義は拒否します。素材の種類をまたいで数量を足しません。安全な整数の範囲を超える合計はエラーにします。

素材・費用IDの重複、素材やカードの参照切れ、育成軸の不一致、合法段階の欠落・未知の段階、減少する累計、版不一致はImport時に拒否します。費用bindingの省略は許可し、その育成項目を計算不能にします。100素材/段階、1000段階/定義、全体50000段階、素材・定義・binding各20000件、JSON全体10MiBが上限です。識別子・説明・整数はcatalogの一般規則に従います。

汎用の全段階最大計算では、最大段階は対応groupの最大の段階・スキルLv・rank、Lvの目標は最大特訓段階または最大Snap rankのLv上限です。この画面では共通条件による目標を明示的に指定します。Lv費用表には対応groupの全Lvを登録しますが、上限より先は計算に含めません。既に最大なら追加費用はなく、費用定義が未登録でも計算上は達成済みとし、画面では維持・達成済みの詳細へまとめます。

## EXPと未計算

EXPはLv軸のcumulativeだけに対応します。計算結果は「目標Lvの累計EXP − 現在Lvの累計EXP」で、現在Lvの開始時点からの要求量です。collectionはLv内の途中EXPを保存していないため、これを実際の残り必要EXPとは断定しません。画面と全体集計に上限である旨を表示し、EXPアイテムの効果や個数へ換算しません。

費用定義の欠落・unsupportedは0とせず、項目ごとに理由を表示します。一部が計算不能なら全体は計算済み分の小計です。EXPの上限と確定した素材個数は区別して表示します。異なる費用ルートや代替素材がある場合は、提供者が選んだルートの根拠をbasisに明記してください。代替の選択・最適化機能はありません。

catalogのImportは従来の参照保護と保存失敗保護を使用します。無効なImportは既存catalog/collectionを変更しません。既存のcatalog/collection Exportと変換プロファイルの形式は維持します。旧catalog本体を対象にする互換用ハッシュは新しい任意定義を除外します。

## 表示

必要素材はメンバー／スナップごとに、既存計算結果の消費量を素材別に集計します。同じ素材が両方に必要な場合は別々に表示します。展開するとカード識別バッジ、育成項目、現在→目標段階、消費量を表示します。未計算項目があるセクションは計算済み小計と未計算理由を示し、未知を0にしません。EXPは引き続き上限値の単位で表示します。

絆理論値はバンドごとの横スクロール可能な5列です。キャラランク画面と同じ`progressCharacters`をバンドごとに使い、displayOrderと未指定時の互換順を保持します。展開内訳は相手名と既存ペアランクのみ、相手も同じ表示順です。各ペアを両端のカードに表示し、数値の再計算はしません。未算出理由はカードから確認できます。

## 所持・未所持カードの直接EXP余地

絆カードの概要には最終キャラランク・最終絆合計を保持し、所持カード育成余地、未所持カード獲得余地、目標までの不足EXPを併記します。目標は全キャラ共通で初期30、マスタの合法ランクから選びます。30がない場合は30以下で最大の合法ランク（なければ最小）を選び、累積EXP行がない目標は未算出にします。目標は画面内の表示条件で、所持・育成設定には保存しません。

`createCharacterExpScenarios()`は`applyTrainingConditions()`・`trainingConditions()`・`estimateCharacterRanks()`・`estimateBondRankTheory()`を共用します。直接EXPは既存の達成条件内訳の絆以外を比較します。所持側の基準は現在→全所持育成後、未所持側は全所持育成後→対象キャラに関係する全未所持を各1枚仮取得・育成後です。概要はそれぞれ独立した全件同時シナリオで計算し、個別増分を合算しません。共有Snapはシナリオ内で1枚だけ追加し、関係する全キャラへ反映します。

仮取得の初期状態は各カードのマスタで合法な最小段階・スキルLvと、その段階の上限以内の最小Lvから作り、同じ共通条件を適用します。定義不足・不整合は未算出です。「変更しない」は既存の軸を維持しますが、Lvは従来どおり合法上限まで上がります。ライブ回数・スタンプ所持・楽曲数を保持し、手入力ランクと絆合計を絆理論値へ使いません。不足EXPは収束後の絆合計を既存EXP計算へ渡した累積EXPと目標行との差分です。未入力進捗の不確実性は残ります。

既存のsummaryで相手別の絆表を開閉します。展開領域の「育成・獲得EXPの詳細」からキャラ別の共有dialogを開き、所持／未所持、種類、名前検索、直接EXP増分の絞り込みと降順、20件ずつの表示で探せます。所持の1枚試算は他のカードを現在状態に固定し、未所持の1枚試算は全所持育成後に追加します。直接増分と絆由来の間接増分を区別し、最終ランク・到達判定も表示します。閉鎖後は詳細ボタンへフォーカスを戻し、条件変更時の絆カード開閉を復元します。

未所持の概要はマスタ登録済み全件を得た場合の理論的余地です。現在のガチャ提供・入手可能性・期待値を示しません。実際の所持・設定を書き換えず、画像、排出率、課金費用、購入計画は扱いません。

## 素材在庫と不足数

「素材在庫を編集」の独立dialogで素材名・IDの検索、現在必要な素材／すべての対応素材、未登録のみ／不足ありの絞り込み、20件ずつの表示を使います。素材辞書の`id/name/unit`だけを参照し、名前から分類や同一性を推測しません。入力は保存ボタンで反映し、空欄で未登録へ戻せます。0と未登録は区別します。検索・ページ移動で入力途中の値を保持し、不正入力や保存失敗では登録内容を変更しません。閉鎖後は入口へフォーカスを戻します。

素材の全体必要量は既存`calculateMaterialRequirementsToTarget()`の`totals`を使用し、メンバー・Snapの両方で使う素材でも在庫を一度だけ充当します。不足数は`max(全体必要量−在庫,0)`。既存のメンバー／Snap消費内訳と`growth-detail`を保持します。在庫が未登録なら不足数も未算出です。未計算項目がある場合、必要量は小計で、不足が正なら「少なくともその数量」、0なら「不足数未確定」と表示します。

`unit: item/card`をその単位で扱い、メンバー／Snapの所持カードや複製数から在庫を推測しません。`exp`は必要EXP上限として従来表示を維持し、在庫入力・不足個数の計算から除外します。対象外単位や削除されたIDの登録値は未対応・参照不能の確認表示へ分離し、必要量と混ぜず保持します。定義が消えてもバックアップに残ります。

在庫はcollection v1の任意`resourceInventory`に保存する残高スナップショットです。保存キー・format/versionは維持し、在庫なしの旧v1は変換不要です。追加項目を知らない旧アプリへの逆方向の読込には対応しません。Exportに含め、Importの全体省略時は既存値を保持し、明示オブジェクトは全置換します。素材名・版の更新では同じIDの値を維持します。所持・育成の初期化では在庫も解除します。

共通条件変更は必要量と不足量を再計算するだけで、保存したカード状態・在庫を変更しません。在庫登録はランク・絆理論値・育成状態に影響せず、仮想育成で残高を消費しません。「理論EXP余地」と「現在庫だけで実現できるEXP」は別で、後者やショップ交換・ガチャ・購入・育成順序の最適化は今回扱いません。

候補一覧は基準状態の達成数とカード1枚の寄与差分を使って直接EXPを比較します。全Collectionを候補ごとに再評価しません。最終ランク・絆由来EXPは各行の「最終ランク・絆由来EXPを計算」を開いた時に計算します。個別増分0で一覧が空になる場合は、全件同時の閾値達成との違いを説明し、「増分0のカードも表示」から20件ずつ確認できます。
