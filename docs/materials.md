# 必要素材・素材在庫

「必要素材」は、現在のcollectionの全所持Member・Snapを共通育成条件まで育てる費用を表示します。在庫の編集は独立した「素材在庫」、育成理論値・絆内訳・カード別EXPは「キャラランク」にまとめます。不足数は今回のUIに表示しません。課金額、ガチャ期待値、育成効率の最適化、バンドアイテムの素材は扱いません。

## 目標状態と育成成果

評価値画面と同じ`simulateTrainingEvaluation()`で仮想状態を作ります。5項目の目標は「変更しない」または1〜5、現在値を下げず合法な値だけを使います。Member／Snap Lvは段階維持時も育成後の段階に対応する上限へ設定します。共通ダイアログ、旧4項目設定の移行・保存保護は[共通育成シミュレーション](training-simulation.md)を参照してください。

素材は`calculateMaterialRequirementsToTarget()`で現在→目標の差分だけを計算します。覚醒・Snap上限解放を指定して上がる場合、その現物要求も含みます。未知の費用は未計算です。catalog／collectionを変更せず、入力進捗・手入力・アイテム・その他の所持情報を保持します。

キャラランク画面の育成理論値は、同じ育成状態に既存の絆反復計算を適用します。手入力キャラランク・絆合計を除外し、pendingでは数値を補完せず理由を表示します。保存形式・計算仕様は変更しません。

## 表示と集計範囲

必要素材画面は共通育成条件と必要素材を表示します。

- 必要素材は既存の`result.materials.totals`と`resources`を使い、素材名と総量を常時表示します。展開すると`cards[].axes[].amounts`を素材IDで逆引きしたカード×育成項目別の消費先を表示します。同一カードの特訓と覚醒も別行です。各消費先の合計は総量と一致し、共有Snapは一度だけ含まれます。
- 費用の根拠・理由・現在→目標は消費先の計算詳細で確認できます。未計算項目は独立した詳細に集め、素材IDが不明な項目を特定素材に関連付けません。一部未計算なら総量は計算済み分の小計です。

条件変更時は必要素材と展開内容を更新します。素材在庫・絆・EXPの旧表示はこの画面に残しません。

通常素材・ゲーム内通貨はマスタの素材名・単位で表示し、EXP要求量は分けます。汎用素材定義には希少性・通貨専用の分類がないため、名前／IDから優先順位や分類を推測しません。注意は該当箇所に短く表示し、計算条件・根拠・保留理由は詳細から参照できます。

素材定義を含むcatalog JSONを「JSON Import / Export」のマスタからImportしてください。定義を持たない既存catalogも引き続き有効です。

## 定義契約

catalog v1の任意項目`materialDefinition`に以下を内包します。別の保存キーは作りません。素材在庫はcollection v1の任意項目で、在庫なしの旧collectionは従来どおり読み込めます。読込だけでは保存バイト列を書き換えません。実定義は同梱せず、ブラウザから取得・変換・送信しません。

| 項目 | 内容 |
| --- | --- |
| catalogRevision | 包含するcatalogのrevisionと完全一致する識別子 |
| resources | 素材のid・name・unit（item:個、card:枚、exp:EXP要求量） |
| schedules | id・axis・mode・basis・stages、任意のreason |
| bindings | kind（member/snap）・cardId・axis・scheduleId |

axisはMemberの`trainingStage`・`awakeningStage`・`liveSkillLevel`・`gekisouSkillLevel`・`level`、Snapの`rank`・`level`です。名称と費用の根拠`basis`は提供者が登録し、画面ではテキストとして表示します。

scheduleのmodeは`steps`（到達段階ごとの消費）、`cumulative`（その段階までの累計）、`unsupported`（確認できない費用）です。stagesは`stage`と`amounts: [{resourceId, quantity}]`を持ちます。配列順は意味を持ちません。初期段階のsteps費用は空配列または明示0、以後の消費なしも空配列で明示します。行の欠落を消費0とは解釈しません。unsupportedには空のstagesと必須のreasonを設定します。

計算はstepsなら現在値より大きく目標以下の行を合算し、cumulativeなら目標の累計から現在の累計を引きます。累計から省略した素材は0として扱うため、以前存在した正の数量を省略して減らす定義は拒否します。素材の種類をまたいで数量を足しません。安全な整数の範囲を超える合計はエラーにします。

素材・費用IDの重複、素材やカードの参照切れ、育成軸の不一致、合法段階の欠落・未知の段階、減少する累計、版不一致はImport時に拒否します。費用bindingの省略は許可し、その育成項目を計算不能にします。100素材/段階、1000段階/定義、全体50000段階、素材・定義・binding各20000件、JSON全体10MiBが上限です。識別子・説明・整数はcatalogの一般規則に従います。

汎用の全段階最大計算では、最大段階は対応groupの最大の段階・スキルLv・rank、Lvの目標は最大特訓段階または最大Snap rankのLv上限です。この画面では共通条件による目標を明示的に指定します。Lv費用表には対応groupの全Lvを登録しますが、上限より先は計算に含めません。既に最大なら追加費用はなく、費用定義が未登録でも計算上は達成済みとし、画面では維持・達成済みの詳細へまとめます。

## EXPと未計算

EXPはLv軸のcumulativeだけに対応します。計算結果は「目標Lvの累計EXP − 現在Lvの累計EXP」で、現在Lvの開始時点からの要求量です。collectionはLv内の途中EXPを保存していないため、これを実際の残り必要EXPとは断定しません。画面と全体集計に上限である旨を表示し、EXPアイテムの効果や個数へ換算しません。

費用定義の欠落・unsupportedは0とせず、項目ごとに理由を表示します。一部が計算不能なら全体は計算済み分の小計です。EXPの上限と確定した素材個数は区別して表示します。異なる費用ルートや代替素材がある場合は、提供者が選んだルートの根拠をbasisに明記してください。代替の選択・最適化機能はありません。

catalogのImportは従来の参照保護と保存失敗保護を使用します。無効なImportは既存catalog/collectionを変更しません。既存のcatalog/collection Exportと変換プロファイルの形式は維持します。旧catalog本体を対象にする互換用ハッシュは新しい任意定義を除外します。

## 表示

必要素材はメンバー／スナップごとに、既存計算結果の消費量を素材別に集計します。同じ素材が両方に必要な場合は別々に表示します。展開するとカード識別バッジ、育成項目、現在→目標段階、消費量を表示します。未計算項目があるセクションは計算済み小計と未計算理由を示し、未知を0にしません。EXPは引き続き上限値の単位で表示します。

## キャラランクとカード別EXP

キャラランクの横スクロールカードはPC 192px、モバイル224pxを基本とします。現在ランク（手動上書きと自動推定を区別）、所持カードを共通育成条件まで育てた絆最大時の育成理論値、現在→理論値の回収可能EXP（育成＋絆）、理論値→目標の不足EXPを表示します。全未所持同時取得ランク、所持カードの直接EXP単純合計・未所持全取得の総EXP増分、絆合計の常時表示は行いません。「進捗・ランク入力」「絆内訳」「カード別EXP」は独立した入口です。絆合計とペア別結果は絆内訳内に表示し、開閉・下書き・横スクロールを条件変更時に維持します。

目標は数値入力、初期30です。マスタの合法ランクだけを確定し、不正値には通知して直前の確定目標を保持します。初期30が非法なら通知し、別ランクへ勝手に置換しません。累積EXP行がなければ不足EXPは未算出です。所持・育成条件の保存値を変更しません。

`createCharacterExpScenarios()`は`applyTrainingConditions()`・`trainingConditions()`・`estimateCharacterRanks()`・`estimateBondRankTheory()`を共用します。不足EXPは育成後・絆反復収束後の累積EXPと目標行との差分です。手入力ランク・絆合計を理論計算に混ぜません。未入力進捗は加算せず不確実性を表示します。

カード別EXPは所持／未所持タブ（初期は所持）の内側にメンバー→スナップのセクションを並べます。未所持は所持管理と同じ薄い表示にします。識別表示・バッジ・色・段階列を既存所持管理と共用します。所持切替・育成編集はできません。現在・目標の段階を色と文字で示し、Lvも現在→目標を表示します。未所持に現在の段階を作りません。名前・タイトル・ID検索、所持状態×種類ごとに独立した20枚ずつの表示、上部の固定閉じるボタン、Esc・Tab循環・フォーカス復帰に対応します。起動時は検索入力ではなく見出しへフォーカスします。タブは左右矢印・Home・Endでも操作でき、切替時に検索語と各分類の表示件数を保ちます。

所持カードは他のカードを現在状態に固定し、その1枚だけを育成した直接EXP増分です。未所持は全所持育成後を基準にその1枚を取得・育成した増分です。仮取得の初期状態はマスタの合法最小段階・スキルLvと、その段階の上限以内の最小Lvから作り、共通条件を適用します。非加算の達成閾値を維持し、個別増分を足して一括結果としません。基準の達成数に1枚の寄与差分を適用し、候補ごとの全Collection投影はしません。最終ランク・絆由来EXPは各カードの補助詳細を展開した時だけ計算します。所持分は画面の育成理論値に含まれ、未所持分はその先の候補です。現在の入手可能性・ガチャ提供を示しません。

## 素材在庫

独立した「素材在庫」画面で素材名・単位・現在庫を表示します。所持管理の一覧・検索・入力スタイルを使い、個・枚の全素材を初回から表示し、検索結果も全件表示します。入力欄は数値入力（min=0、step=1）とし、非負の安全な整数だけを保存します。負数・小数・指数表記・不正な途中入力は保存せず、入力中のホイールによる数値変更を防ぎます。素材名・IDで検索でき、変更は350ms後または入力確定時に自動保存します。画面移動前にも保存待ちを反映し、長い一覧の最下部に保存・閉じるボタンは設けません。空欄は未登録、明示0は在庫0です。不正値・保存失敗では既存在庫を変更せず、エラーと入力途中の値を保持します。検索・画面移動で未保存入力を保持し、正規のImport・初期化では破棄します。

在庫はcollection v1の任意`resourceInventory`で、保存キー・format/versionを維持します。旧v1は変換不要、読込だけでは保存バイト列を変更しません。Exportに含め、Importでフィールド全体省略なら保持、明示オブジェクトは置換します。素材の改名・版更新はIDの登録値を維持します。削除IDや対象外EXPの登録値は補助表示で確認でき、編集・削除せずバックアップへ保持します。所持・育成データの初期化では在庫も解除します。

EXPは必要EXPの上限値であり在庫個数には換算しません。不足計算エンジン`materialInventoryBalances()`は従来どおり保持し、全体必要量から在庫を一度だけ控除しますが、今回の画面では使用・表示しません。在庫は理論ランク・EXP・必要素材の計算に影響せず、仮想育成で消費されません。
