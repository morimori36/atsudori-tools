# 育成余地・素材

現在のcollectionの全所持Member・Snapを**3画面共通の育成条件まで育てた場合**の成果と費用を比較します。課金額、ガチャ期待値、素材所持数・不足数、育成効率の最適化、バンドアイテムの素材は扱いません。

## 目標状態と育成成果

評価値画面と同じ`simulateTrainingEvaluation()`で仮想状態を作ります。5項目の目標は「変更しない」または1〜5、現在値を下げず合法な値だけを使います。Member／Snap Lvは段階維持時も育成後の段階に対応する上限へ設定します。共通ダイアログ、旧4項目設定の移行・保存保護は[共通育成シミュレーション](training-simulation.md)を参照してください。

素材は`calculateMaterialRequirementsToTarget()`で現在→目標の差分だけを計算します。覚醒・Snap上限解放を指定して上がる場合、その現物要求も含みます。未知の費用は未計算です。catalog／collectionを変更せず、入力進捗・手入力・アイテム・その他の所持情報を保持します。

絆理論値は`result.bondTheory(bandId)`のready結果をそのまま表示し、手入力キャラランク・絆合計を除外します。pendingでは数値を補完せず理由を表示します。評価値画面・JSON出力・保存形式・計算仕様は変更しません。

## 表示と集計範囲

表示順は共通育成条件、必要素材、絆理論値です。

- 必要素材は既存の`result.materials.totals`と`resources`を使い、素材名と総量を常時表示します。展開すると`cards[].axes[].amounts`を素材IDで逆引きしたカード×育成項目別の消費先を表示します。同一カードの特訓と覚醒も別行です。各消費先の合計は総量と一致し、共有Snapは一度だけ含まれます。
- 費用の根拠・理由・現在→目標は消費先の計算詳細で確認できます。未計算項目は独立した詳細に集め、素材IDが不明な項目を特定素材に関連付けません。一部未計算なら総量は計算済み分の小計です。
- 絆理論値はキャラランク入力画面と同じ表示順で、finalRank（最終キャラランク）とbondRankTotal（最終絆合計）を常時表示します。各キャラを展開すると関係するペアとrankを表示します。ペアは両キャラに表示し、それぞれの合計がbondRankTotalと一致します。未入力進捗の注意を維持します。

条件変更時は両セクションと展開内容を更新します。理論上の到達値であり、獲得済みの絆ランクではありません。バンド・キャラ単位の素材小計、カード階層、独立したSnap内訳は設けません。

通常素材・ゲーム内通貨はマスタの素材名・単位で表示し、EXP要求量は分けます。汎用素材定義には希少性・通貨専用の分類がないため、名前／IDから優先順位や分類を推測しません。注意は該当箇所に短く表示し、計算条件・根拠・保留理由は詳細から参照できます。

素材定義を含むcatalog JSONを「JSON Import / Export」のマスタからImportしてください。定義を持たない既存catalogも引き続き有効です。

## 定義契約

catalog v1の任意項目`materialDefinition`に以下を内包します。別の保存キーは作らず、collectionの形式・保存バイト列を変更しません。実定義は同梱せず、ブラウザから取得・変換・送信しません。

| 項目 | 内容 |
| --- | --- |
| catalogRevision | 包含するcatalogのrevisionと完全一致する識別子 |
| resources | 素材のid・name・unit（item:個、card:枚、exp:EXP要求量） |
| schedules | id・axis・mode・basis・stages、任意のreason |
| bindings | kind（member/snap）・cardId・axis・scheduleId |

axisはMemberの`trainingStage`・`awakeningStage`・`liveSkillLevel`・`gekisouSkillLevel`・`level`、Snapの`rank`・`level`です。名称と費用の根拠`basis`は提供者が登録し、画面ではテキストとして表示します。

scheduleのmodeは`steps`（到達段階ごとの消費）、`cumulative`（その段階までの累計）、`unsupported`（確認できない費用）です。stagesは`stage`と`amounts: [{resourceId, quantity}]`を持ちます。配列順は意味を持ちません。初期段階のsteps費用は空配列または明示0、以後の消費なしも空配列で明示します。行の欠落を消費0とは解釈しません。unsupportedには空のstagesと必須のreasonを設定します。

計算はstepsなら現在値より大きく目標以下の行を合算し、cumulativeなら目標の累計から現在の累計を引きます。累計から省略した素材は0として扱うため、以前存在した正の数量を省略して減らす定義は拒否します。素材の種類をまたいで数量を足しません。安全な整数の範囲を超える合計はエラーにします。

素材・費用IDの重複、素材やカードの参照切れ、育成軸の不一致、合法段階の欠落・未知の段階、減少する累計、版不一致はImport時に拒否します。費用bindingの省略は許可し、その育成項目を計算不能にします。100素材/段階、1000段階/定義、全体50000段階、素材・定義・binding各20000件、JSON全体10MiBが上限です。識別子・説明・整数はcatalogの一般規則に従います。

汎用の全段階最大計算では、最大段階は対応groupの最大の段階・スキルLv・rank、Lvの目標は最大特訓段階または最大Snap rankのLv上限です。この画面では共通条件による目標を明示的に指定します。Lv費用表には対応groupの全Lvを登録しますが、上限より先は計算に含めません。既に最大なら追加費用はなく、費用定義が未登録でも計算上は達成済みとし、画面では維持・達成済みの詳細へまとめます。

## EXPと未計算

EXPはLv軸のcumulativeだけに対応します。計算結果は「目標Lvの累計EXP − 現在Lvの累計EXP」で、現在Lvの開始時点からの要求量です。collectionはLv内の途中EXPを保存していないため、これを実際の残り必要EXPとは断定しません。画面と全体集計に上限である旨を表示し、EXPアイテムの効果や個数へ換算しません。

費用定義の欠落・unsupportedは0とせず、項目ごとに理由を表示します。一部が計算不能なら全体は計算済み分の小計です。EXPの上限と確定した素材個数は区別して表示します。異なる費用ルートや代替素材がある場合は、提供者が選んだルートの根拠をbasisに明記してください。代替の選択・最適化機能はありません。

catalogのImportは従来の参照保護と保存失敗保護を使用します。無効なImportは既存catalog/collectionを変更しません。既存のcatalog/collection Exportと変換プロファイルの形式は維持します。旧catalog本体を対象にする互換用ハッシュは新しい任意定義を除外します。
