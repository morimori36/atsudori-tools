# CIの検証範囲の読み方

Actionsの実行画面のSummaryに、verifyジョブの「検証範囲」を表示します。checkout SHAは実際に検証したcheckout（PRでは通常merge commit）、PR head SHAは提出ブランチの版です。PR以外でPR head SHAを取得できない場合は取得不可と表示します。

| 表示 | 意味 |
| --- | --- |
| ステップ結果 | GitHubのoutcome。元の検証の失敗を集計処理で成功へ変えません |
| 成功・失敗 | JSONレポートに記録されたテストケースの件数 |
| 意図的skip | 明示的な理由と実行条件を登録した保留。このCIでは現在登録なし |
| 環境skip | 前提不足・非対応環境に一致する登録済みskip。このCIでは現在登録なし |
| 想定外skip/pending | 登録されていないskip、または未完了のpending。理由を調査し、検証済みに含めません |
| todo | 未実装の検証。skipや成功に含めません |
| 再試行で成功 | Playwrightのflaky件数。成功件数の内数で、試行回数をテスト数へ足しません |
| 未実行 | 前段の失敗や条件分岐等でステップを実行していない状態 |
| レポート欠落・不正 | 件数とテスト実施範囲は不明。型検査・buildで止まった場合も含み、0件成功や必ず未実行とは扱いません |

型検査・Schema同期・公開監査・集計処理自体のテストはステップ結果を示し、型検査の成功後に生成された単体レポートと区別します。ケース以外のブラウザ全体エラーも別に示します。ステップが未実行の場合はレポートを読まず、古いレポートを今回の結果として表示しません。

ChromiumとWebKitは別の実行です。WebKitは設定で選んだテストだけで、実機Safariを検証したことにはなりません。ナビゲーション撮影とartifact保存は既存のPR限定ステップで、PR以外では未実行と表示します。撮影成功は画像の内容レビューの完了を意味しません。外部の非公開回帰はこのCIへ入力しません。各行のテストは重複するため総合計を作らず、ゲーム仕様や観測の正しさの保証にも使いません。

既存の検証コマンド・失敗条件・配信条件を維持し、レポーターの追加で件数を収集します。集計処理は`if: always()`で前段失敗時も実行し、集計自体の失敗で元の結果を上書きしません。ジョブ強制終了等でSummaryが生成されない場合は元のステップ結果を確認してください。verifyの成功とPages配信の完了は別で、配信はdeployジョブを確認します。

生のJSONレポートはGit対象外の`.cache/ci/`にだけ保存し、配信物・追加artifactには含めません。Summaryには集計値・固定ラベル・検証SHAのみを出し、テスト名・ファイルパス・入力・例外本文を転載しません。集計の回帰は`node --test scripts/ci/report.test.mjs`で確認できます。
